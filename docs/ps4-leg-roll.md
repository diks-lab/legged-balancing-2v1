# 左スティック左右・姿勢補正の有効化

基準8a5d75a。利用者の実測：水平付近AngleX−0.9°、左下がり−9.1°。
右脚伸長で右側が高くなり左へ傾く。この対応に基づきesp32devだけで
`LEG_ROLL_DIRECTION_CONFIRMED=1` / `LEG_IMU_ROLL_SIGN=-1`を設定する。
定義はplatformio.iniへ一組だけ。ヘッダーの未指定時既定値は未確認のままとし、
単独試験や別ファームへ無条件に有効化を波及させない。
−0.9°はオフセットとして差し引かない。NVS脚校正・車輪FOCとは別の変更。

## 符号と制御

- 受信LX負→左正の目標、LX正→右目標。既存の`-legAxis(lx)`を変更しない。
  **物理的な左右とLXの対応は今回未確認**。シリアルのraw_LX_LY／PS4 AXESで照合する。
- LY正→伸長、LY負→短縮。最大12ポイント/秒、DZ±16・再操作中央±10は不変。
- 通信タスクではなく制御側の既存キャッシュから、左正実測角＝−AngleXを一度だけ作る。
- 左右目標は最大2°/秒、±3°。中央で2°/秒で0°へ戻す。
- 既存式`左右差=P×(適用目標−左正実測角)`、P=1ポイント/度、差の変化上限4ポイント/秒。
  左目標は右伸長・左短縮、左下がりの実測に対する0°補正は右短縮・左伸長。
- 左右差を伸長率で合成して左右別tickへ変換する。高さを勝手に変えず、可動余裕で
  適用目標／補正を制限する。通常範囲・物理端・10tick余裕・通信50ms・速度150・加速度15は不変。
- 初回同期は取得tickを完全一致で保持。新しい左右入力が来るまで補正を始めない。
  範囲外保持・戻し中も目標と補正は無効。通常へ戻った後の新しい左右操作から補正する。
- 切断時は未送信増分を捨て最後の送信位置を保持し、左右目標を消去。
  再接続・転倒／停止・走行優先後は既存の左中央／新操作／再同期を要求し、古い目標を再開しない。

## 診断

Webは生AngleX・左正実測角・要求／適用目標、最終送信tickと計算tick、
可動制限を区別する。現時点の位置を読み続けている表示ではない。
制限欄は上下端・左右差の可動余裕不足を明示し、拒否理由は確定状態欄に表示する。
既存1Hz詳細診断の値を使用し、JSON項目・送信バッファを追加しない。

シリアルは既存LEG MOTION／UART／TORQUEにLEG ROLLを追加。
生AngleX・左正実測角・要求／適用目標・制限フラグを同じ記録から表示する。
LXと実機の左右を照合できる注記を付ける。連続操作は最大2Hzの最新値集約、
出力は後処理・最大48B/回、コールバック／受信／制御中の直接出力・待機は追加しない。

## 検証と資源

- productionのbuild_flagsを読み込むPS4コールバック→FIFO→制御→UART試験を追加。
  左右目標とAngleXの符号、傾きを減らす補正、中央戻し、斜め入力、上下端、
  高さ不変・通常範囲内、初回完全一致保持、範囲外戻し、切断再接続を確認。
- 既存の未確認設定回帰は明示的な比較として維持。23組ホスト回帰が成功。
- 脚・UART・脚NVS・実制御経路・配信のASan/UBSan成功。
- Chromium＋模擬データ1366×768／1920×1080の100%、125%相当の脚欄表示が成功。
  生／変換角、補正有効表示、長い理由の折返し、既存グラフ表示を確認。
  実コントローラーや実機センサーを接続したブラウザー試験ではない。
- ESP32ビルド・LittleFS生成成功。既存ファイルのLF／CRLF双方8192B上限と直列読込みを維持。

8a5d75a比で静的RAM84,356→84,516 B（+160 B）、Flash1,949,329→1,949,613 B（+284 B）。
ホスト上のシリアル記録器968→1112 B、イベント72→84 B、出力器280→304 B。
Control532 B／State508 B／Snapshot1124 B、固定出力文字列192B、FIFO件数、タスク・スタックは不変。
JSON形式・20Hz選択配信は不変。最大詳細JSONの確認例1831 B／既存2048 B。
有効フラグのfalse→trueで実パケットは1B短くなる。Webに追加する数値は既存データの表示。
実機のヒープ・周期への影響、**脚指令による傾斜・補正動作は未検証**。
左車輪不動、PS4切断、前進・振動問題の解決とは扱わない。

## 更新と最初の実機確認

**ファームとLittleFSの両方を更新。校正NVSの再登録は不要。**
本作業では実機書込み・マージを行わない。

```sh
pio run -e esp32dev
pio run -e esp32dev -t buildfs
# 以下は利用者が支持・停止手段を準備して実施
pio run -e esp32dev -t upload
pio run -e esp32dev -t uploadfs
```

1. 外部電源コードを脚・車輪から離し、機体を確実に支持する。
   車輪は従来の起立条件で動き得るため×停止→全中央・解放→Share→解放で支持試験。
2. 上下の初回同期では取得tickが保持されることを確認。範囲外は左中央後の新しい内向き上下操作だけで戻す。
3. 両脚を通常範囲の中間へ置き中央へ戻す。両方向に余裕があること、補正有効表示、
   生AngleX／左正角を確認する。水平時−0.9°でも0°補正との差は残る。
4. 左を小さく短く倒し、raw LXが負か確認。要求目標が正、右目標tick減少・左も減少することを
   calc_RL／last_RLで確認する（左は短縮）。物理方向が逆なら続行せずログを共有する。
   今回はLXの推測反転をしていない。
5. 中央で目標0°へ戻ること、右の小操作では逆になることを確認。
   支持したまま小さく左右へ傾け、左下がりでは右短縮／左伸長、右下がりでは逆に補正することを見る。
6. 指令と実追従・可動余裕を確認してから静止倒立中の小操作へ進む。
   走行併用は対象外。指令方向が正しいことと、荷重下で安全に追従することは別に確認する。
