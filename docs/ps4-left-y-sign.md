# PS4左Yの実測符号の反映

基準 `129ee91`。利用者の実測では、物理的な上入力がLY=+127。
従来の `height = -legAxis(LY)` が逆方向を指示していたため、
`LegControl::rawStick()`だけを `height = legAxis(LY)` へ変更した。

- 上＝LY正＝伸長要求正＝右tick減少／左tick増加。
- 下＝LY負＝短縮要求負＝右tick増加／左tick減少。
- 中央＝高さ指令保持。

共通の比例曲線 `legAxis` は変更しない。DZ±16、再操作中央は両軸±10、
正側+127／負側−128で各最大値、最大4ポイント/秒を維持する。
例えばLY=+72は+56/111（約+0.5045）、LY=−72は−56/112（−0.5）。
新しいフィルター・ランプ・速度変更は加えない。

右Y・右X・左Xの変換は変更しない。左Xは従来の負号を維持し、
左右方向確認フラグも無効のまま。斜め入力では上下だけを適用する。
脚の換算・NVSの4点・余裕・通常範囲・車輪制御にも変更はない。

## 診断

Web・シリアルは、同じheightから生成するUP／DOWN・伸長／短縮・要求／適用値を表示する。
表示側でさらに符号を変えない。生LYも取得した値のまま保持する。
旧ファームのログを書き換えたり、新しい符号のログとして解釈し直したりしない。

修正版の下入力の例：

```text
raw_LX_LY=0/-128 applied=-1.000/+0.000
```

上入力は `raw_LX_LY=0/127`、受理・適用されれば上下要求／適用は+1、UP／伸長となる。
同期中、中央待ち、可動制限や拒否状態では、要求があっても適用0になり得る。
[計算目標とUART送信の確認](leg-command-diagnostics.md)と併せて読む。

## 確認結果

実際のPS4コールバック→FIFO→入力ゲート→脚目標→UARTフレームまで通して確認した。

| 条件 | LY正 | LY負 |
|---|---|---|
| 通常範囲内 | 右tick減少・左増加 | 右tick増加・左減少 |
| 伸長側の通常範囲外 | 拒否・取得位置保持 | 初回同期後の中央復帰・新しい操作から短縮 |
| 最縮側の余裕外 | 中央復帰・新しい操作から内側へ伸長 | 拒否・保持 |

初回同期は取得値そのものを保持し、中央確認前の倒し替えでは移動しない。
中央保持、左Xを含む斜め操作、再接続後の倒しっぱなし拒否も確認した。
切断時には既存どおり位置保持が残る場合があるが、古い入力から目標更新を再開しない。
生値観測だけで古い指令が再適用されないこと、右走行・旋回の既存回帰も確認した。

100%位置（右1697／左2408）から中央→新しい下LY=−128を3秒保持したホスト試験では、
計算・最終送信とも右1739／左2369 tick、位置61回（初回保持を含む）、ON1回だった。
これはUART writeまでの確認で、実機の追従成功を意味しない。

ホスト回帰23組、脚／送信／保存／実制御経路／配信のASan・UBSan、
Chromium＋模擬データ、ESP32ビルド・LittleFS生成が成功した。
静的RAMは84,356 Bのまま、Flashは1,948,049→1,948,037 B（−12 B）。
実機の制御周期・ヒープ・修正後の動作は未測定。

## 更新と実機確認

**ファーム＋LittleFSの両方を更新する。保存校正の再登録は不要。**
校正値・保存形式は変えていない。実機書込み・マージは本作業で行わない。

1. 外部電源コードを脚・車輪から離して機体を支持し、×停止。
2. 中央・全解放→Share→解放。初回同期で保持した後、左XYを中央へ戻す。
3. 伸長側の通常範囲外なら、新しい**下操作（LY負）で短縮**して通常範囲へ戻す。
4. 中央で保持を確認し、次に**上操作（LY正）で伸長**を小さく確認する。
5. `applied`、`calc_RL`、`last_RL`、送信回数と待ち／失敗を比較する。

コントローラー切断の原因は未確定の別件。この符号修正で解決したとは扱わない。
左車輪不動の調査も保留のままである。
