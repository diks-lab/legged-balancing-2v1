# 2208 AttitudeOnly 初回確認

基準: `codex/wheel-velocity-test` / `89d7deda24d0c807e5f6358afab2fcba53d1f046`。
**実機で旧符号の逆方向を確認済み。今回の符号修正は実機未検証。接地して自立させる試験ではない。**

## 制御経路と符号

- 配線・7極対・torque/voltage を維持。供給電圧とドライバー相電圧範囲は8.3 V。
  アライメント2 V、両輪の初期化完了後にモーターUq上限を1 Vへ下げる。
- 診断で確認済みの「右＋・左＋は車体前進」を車体方向の定数として明示。
  SimpleFOCが検出する `sensor_direction` は電気角とshaft値の補正に使い、
  車体方向の係数へ再利用しない。位置・速度は左右のshaft値を各＋0.5で平均し、
  単位はrad・rad/s（m・m/sへの変換ではない）。
- 毎ループ、右 `loopFOC()` → 異常確認 → 左 `loopFOC()` → 異常確認 →
  MPU更新 → 更新済みセンサーからshaft値を取得 → 倒立計算 → 左右 `move()`。
  追加のセンサーI2C読み取りは行わない。SimpleFOC 2.4.0の `move()` が後で
  再取得するshaft値を待たず、倒立計算前に最新のキャッシュを使う。
  `move()` は次の `loopFOC()` 用の指令を設定するため、PWM反映には1ループの遅れがある。
- `test_LQR_u = pid_angle(AngleY - angle_zeropoint) + pid_gyro(GyroY)`。
  左右とも `clamp(+test_LQR_u, -1 V, +1 V)` を `move()` へ渡す。
  角度はdeg、角速度はdeg/s。既存Pゲイン1と0.08を維持。
  実機で前傾＋5.93 deg→旧出力−1 V、後傾−9.87 deg→旧出力＋1 Vを確認したため、
  AttitudeOnlyの出力符号を反転し、前傾→正電圧・後傾→負電圧に修正。
  実駆動・ステータス・トレースに共通の変換を使う。sensor_directionと車体方向係数は変更しない。
  printLqrStatusはPIDを再計算せず直前の制御値を表示し、位置・速度項は0表示とする。
- 既存AttitudeOnlyを初期値として固定。位置・速度項は0、待機ブレーキはOFFで固定。
  `g` / Webのモード切替を拒否し、共通の走行要求入口で走行を拒否する。
  PS4固有の処理、脚、C3、wheel_diagnostic.cppは変更しない。
- 診断の速度PID、50 ms LPF、5 V/sランプは移植しない。
  shaft速度LPFはSimpleFOC既定の5 ms、既存の制御用速度平滑化も変更しない。
  姿勢項だけの出力にはそれらの速度値を加算しない。

## 起動・有効化・停止

既存の起動順とBalance Waitを使用する。起動時にはENをLOWにしてからピンを出力化。
両AS5600を検査してから、従来どおりsetup内でMPUの校正と左右のFOC初期化を行う。
**起動時の2 Vアライメントで車輪は動く。倒立出力が無効でも、起動が無動作とは限らない。**
両輪のdriver/init/FOC/極対数チェック成功、センサー正常を確認してから、
上限を1 Vに下げてゼロ指令で両ドライバーを有効化する。倒立は未armのまま。

`t`（または既存Web START）が明示的な倒立開始要求。初期化成功・非常停止解除・
他試験非実行が条件。2秒準備後、既存の安定判定を満たして連続1.5秒計測すると、
平均角をゼロ点としてAUTO STARTする。開始候補は |gyro|≦2 deg/s、
|wheel speed|≦0.8 rad/s。計測中は候補角から±2 deg、|gyro|≦4 deg/sと
同じ車輪速度条件で連続安定を判定する。条件不成立時のリセット動作も既存のまま。

停止経路:

- `d`: 既存の試験解除経路で出力をゼロにし、両輪ドライバーを無効化。
  ゼロ指令時は、次のFOCを待たずPWMもゼロにする。再開は正常時のみ `u` → `t`。
- 転倒停止: 既存の `confirmActualFall()` を変更しない。
  基準角から20 deg超が80 ms以上、35 deg以上なら30 ms以上、いずれも最低3サンプル。
  既存の非有限値・角度/基準の不連続を除外する条件も維持。
- 左右どちらかのAS5600でNACK、短い受信/タイムアウト、不正データを検出したら、
  読み取りコールバックで両ENをLOWにし、ループで指令・PWMをクリアして試験解除。
  faultをラッチし、`test_system_ready=false` とするため `u` / `t` でも再有効化できない。
  原因を取り除いて再起動する。
- センサー/ドライバー/モーター/FOC初期化失敗、極対数チェック不一致、
  アライメント監視タイマー生成/起動失敗・6秒超過でも両輪停止。自動再試行しない。
  6秒監視は診断同様 `initFOC()` のみで、`motor.init()` の待ち時間は含まない。
- `s` / `0` は既存のゼロ指令操作であり、倒立の解除ではない。
  `e` も走行だけの停止で、倒立を続ける。復元方向試験の中断には **`d`** を使う。

通信異常検出の範囲は、診断で確認済みのAS5600読み取りとその初期化である。
MPU6050ライブラリ自体の受信長検査、磁石状態、正常範囲内のセンサーフリーズ検出は
今回追加しない。独立タイマーもCPU停止やハード故障まで保証するものではない。

## 車輪を浮かせて復元方向を確認する操作

1. 車輪が机・配線・手に触れない状態で、機体を確実に支える治具を用意する。
   小さく前後に傾けられ、落下しないようにする。電流制限付き8.3 V電源と、
   すぐ操作できる物理的なモーター電源遮断を用意する。初期化中はシリアル停止が
   即時処理されないため、必要なら物理的に遮断する。
2. シリアル115200で起動ログを確認する。MPU校正中は静止させる。
   左右FOC成功・方向表示・`both motors initialized and stopped at 0.00 V` を確認。
   `p` で角度と速度を確認する。この時点では倒立出力は出ない。
3. 無出力で符号を先に見る場合は、中立で `z` → `a`、前後にごく小さく傾けて
   `p` を送る。物理的な前傾に対するAngleY/GyroYと表示出力の符号を記録する。
   `a` は計算診断だけでモーターに接続しない。終了は `d`。
4. `d` 後は `u` を1回送りゼロ指令で有効化する。車輪を浮かせ、中立で静止させて
   `t` を1回送る。`ATTITUDE ONLY`、待機ブレーキOFFを確認し、2秒準備と
   1.5秒の安定判定後の `LQR Direction Test AUTO START.` を待つ。
   `g`、`b`、走行要求で位置/速度項を追加することはできない。
5. 支えたまま、最初は0.2～0.5 deg程度だけゆっくり前傾させる。
   両輪が「接地したなら前進する」方向へ動くか、ごく短時間で確認する。
   小さく後傾させた場合は両輪が逆向きになることを確認する。
   角度・gyroに対する出力は左右同符号で、各±1 V以内であることを確認する。
   浮いた車輪では車体の角度を戻せず回転が続くので、姿勢を保ったまま待たない。
6. 逆向き、片輪だけ逆向き、異音、想定外の回転があれば直ちに `d`。
   応答しなければ物理的にモーター電源を遮断する。試験終了も `d`。
   前傾符号を記録してから原因を検討し、このPRのまま接地試験へ進まない。

修正後の復元方向、実電圧、発熱、I2C故障時の実EN遮断、停止距離は**実機未検証**。
ビルド成功やホスト試験は、倒立安定性や実機での安全性を保証しない。
