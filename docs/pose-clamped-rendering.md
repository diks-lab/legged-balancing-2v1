# 姿勢グラフの範囲外表示

基準はd59c137。今回の製品コード変更はdata/plot.jsのみ。

## 原因

従来の描画は姿勢を0°で補完していない。
有効な−48.9°を±30°軸の外へ投影した後、Canvasの描画枠で切り取っていた。
その結果、0°の灰色破線（中央軸）と、基準角0°の紫の線だけが見え、姿勢線が見えなくなる。
初回の単一点もmoveToだけで線幅を持たず、見えなかった。
機体を傾けた状態が0°であるという意味ではない。

## 修正

姿勢専用グラフでは描画座標だけを−30°～＋30°へ制限する。
範囲外の連続受信は端の線となり、範囲内へ戻れば実際の角度へ連続する。
初回・欠落後の単独の有効点は同じ信号色の半径2 pxの点で表示する。
描画枠を2.5 pxだけ広げ、上下端の線幅や初回点が欠けないようにした。軸の範囲は不変。
姿勢角は青、基準角は紫、中央0°軸は灰色破線。既存の凡例・表示切替を維持する。

無効値・未取得は点も線も描かず、欠落／再接続の前後を結ばない。
起動・履歴消去後も0°や直前値で補完しない。
元の受信値、履歴、CSV、実角度の数値と範囲外マーカーは変更しない。
小数1桁表示、左右ドーナツ、補助グラフ、通信、制御・安全処理は変更しない。

## 検証

- Nodeの実描画コード試験：−48.9°初回、範囲外継続、−30°／範囲内復帰、正側超過、
  未取得・null・欠落・再接続・履歴消去。元の値とCSVが不変であることを確認。
- Chromium＋模擬WebSocket、1366×768／1920×1080・100％：既存画面の回帰に加え、
  実Canvasの画素で上下端の初回点、端の線、範囲内への線を確認。
  端より外側にも点の画素が残り、枠で欠けないことを確認。
- 履歴／購読・直列取得、LF／CRLFの各ファイル8192 B上限のホスト試験成功。
- ESP32ビルド・LittleFSイメージ生成成功。

実機・ESP32との実通信での表示は未検証。
ファームは不変でRAM 81852 B／Flash 1916193 B。ESP32側のRAM・通信量に変更はない。

## 更新対象

d59c137対応ファームを使用中ならLittleFSだけ更新する。通常ファームの再書込みは不要。

```sh
pio run -e esp32dev -t buildfs
# 利用者が停止・安全を確保して実行
pio run -e esp32dev -t uploadfs
```

ページを再読込みし、約−48.9°の姿勢が下端に青で表示され、紫の基準角が0°に残ることを確認する。
傾きを戻したときの線、配信停止・再接続・履歴消去後の初回点も確認する。
本作業ではマージ・実機書込みを行っていない。
