# 脚の補正量と小刻みな指令の切り分け

基準6ef0d79。最新取得時点の追加変更はなかった。
P=2→3は独立コミット8f7c0ce。補正量の変更は[脚左右P3](leg-roll-p3.md)を参照。
本変更は位置の整数化による不要な往復送信を減らす。実機の「クックック」の原因全体を確定したものではない。
AGENTS.md、upstream-origin.md、脚制御・送信・実位置／USB診断文書を確認した。

## 照合した事項

`SMS_STS::SyncWritePosEx`（src/Servo_STS3032.cpp）は41番から7B/軸のSyncWriteを作る。
内容はACC15・位置L/H・44/45番の0・速度150 L/Hで、ServoBusの24Bフレームと一致する。
既存ドライバーを実行する回帰でON/OFF/位置の全バイト一致を検証し、今回も維持した。
位置指令は最短50ms、左右どちらかの整数目標が変わったときだけ送る。
片側だけ変わった場合も、既存どおり左右の指令／ACC／速度を一緒に送る。

[メーカーのSTS3032仕様](https://www.feetechrc.com/6v-45kg-magnetic-code-360-degree-serial-bus-steering-gear.html)
は4096分割と加減速機能を示す。1tickはサーボ軸約0.088°で、機体傾斜角とは異なる。
[WaveshareのSTメモリー表](https://docs.waveshare.com/Memory_Map_Explanation/ST_Servo_Memory_Map_Explanation)
では41番ACC、42番位置、46番速度を区別し、速度単位は18番phase設定に依存する。
これはST系の資料であり、搭載機の正確な版／phaseは今回未取得。150を150tick/秒と断定しない。
同じACC・速度を書き直すたびに内部の軌道生成が再始動するかは、これらの公開資料と
既存ホストドライバーだけでは確定できない。ACC15・速度150・50ms周期は変更しない。
44/45番の0を、未確認の「50ms補間時間」に書き換えることもしない。

現行校正の可動量は右347tick／左324tick。
左右差4ポイント/秒では約13.88／12.96tick/秒、50msあたり約0.694／0.648tickとなる。
整数位置だけを送るため、滑らかな浮動小数点目標でも0tick／1tickの階段は残る。
サーボが小さい目標へ到達して次の目標を待つ可能性はあるが、実機の速度・加速度プロファイルは未確認。
1Hzの実位置診断だけで50msごとの追従や高周波振動は判定できない。

ソフト側で確認できた問題は、lroundfの0.5tick境界を挟む微小変動が、隣接整数の往復指令を作ること。
同じ50ms列で相対位置0.45／0.55tickを繰り返す試験では、旧処理で99位置送信・
左右合計198tickの不要な往復を再現した。実機でもこの波形だったという断定ではない。

## 最小の指令生成変更

`Control::target()`の整数化だけに、`TargetHysteresisTicks=0.25`を追加した。
最後にUARTへ送れた整数位置qの±0.75tick以内ではqを保持し、外へ出たら従来どおり四捨五入する。
元の0.5tick境界に片側0.25tickの余裕を設け、往復の境界を分離する。
初期値0.25は1tickより小さい比較用の値。機体での十分性は未検証。

- 連続した伸長率・P補正・AngleX・取得実位置は丸めたり平滑化したりしない。
  端数の指令は浮動小数点状態に残し、最後の整数指令への変換だけを安定化する。
- 通常範囲内の有効な最終送信指令を参照。送信失敗で内部の基準だけが進まない。
- 初回プリロード、非active、範囲外保持／戻しは対象外。取得tickの完全一致保持を維持する。
- 既存の通常範囲・端余裕は変えず、目標と保持位置の両方が通常範囲内であるときだけ適用する。
- 最大整数化誤差は旧0.5→0.75tick。通常の上下・左右が共有する位置指令の整数化に作用するが、
  上下12ポイント/秒・左右差4ポイント/秒の連続目標速度は変更しない。
- 小さい方向反転には最大0.25tick分の追加遅れが生じ得る。
  大きな先行目標を送ったり、端を越えたり、余計なサーボ往復で平均値を作ったりしない。
- 正常な連続移動の1tick刻みや内部サーボ制御の振動までは除去しない。
  表示だけを滑らかにした修正ではない。通信周期・加速度・速度・フレーム仕様は不変。

## 検証・資源

同じServoBus経路・50ms列で旧／新を比較し、上記の境界振動は99送信／198tick→0／0になった。
両方向の連続伸縮差と戻りで、指令の逆行なし、誤差0.75tick以内、範囲内、ACC／速度／予約欄不変を確認。
この試験は指令生成の再現であり、サーボを物理的に動かした結果ではない。

ホスト回帰23組、脚／UART／NVS／実PS4制御／配信のASan/UBSan、ESP32ビルドが成功。
P2/P3の同一誤差での1.5倍、変化速度・可動限界、初回完全一致、範囲外復帰、
実PS4入力→UARTの左右・中央復帰、切断／再操作、既定静音・終了後のまとめも回帰確認した。

6ef0d79比の最終ビルド：静的RAM84,764Bで増減0、Flash1,955,221→1,955,309B（+88B）。
状態領域・履歴・タスク・スタック・PS4 FIFO・UART／Webバッファ・READ頻度は不変。
既存の最終送信値を使い、機体に新しい履歴や診断処理を追加しない。

## 更新・実機比較

**ファームのみ更新。LittleFS更新・校正再登録は不要。実機書込み・マージは今回行わない。**

1. 外部電源コードを脚・車輪から離し、機体を支持。既存の×→全中央・解放→Share→解放で支持試験。
2. 同じ通常範囲内の高さ・同じ荷重で、必要ならP3単独の8f7c0ceと最終版を比較する。
3. 左を短く保持してから中央へ戻す。次に右を同じ長さ保持して中央へ戻す。
   「操作中」「入力END後の目標0°復帰」「SUMMARYの新しい実位置」を別々に観察する。
4. 既存`:leg status`、必要な間だけ`:leg log on`を使い、左右tick・目標・実位置差・AngleXを比較。
   コピー前に`:leg log off`。中央へ戻しても、即時にサーボが停止／到達したとは扱わない。
5. 両方向それぞれの傾斜量と、小刻みな往復・振動の増減を記録する。
   通常範囲端では制限が効くため、中間での補正量比較と端での保護確認を分ける。

**P3の実機効果、サーボ追従の滑らかさ、振動改善は未検証。**
通信異常・左車輪不動・PS4切断を修正したとは扱わない。
周期・加速度やサーボ内部設定を追加変更する前に、実機の比較結果を確認する。
