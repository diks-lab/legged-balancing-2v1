# PS4イベント処理

PS4_Controller_Host **1.1.1** の実装を確認し、`attachOnConnect`、
`attachOnDisconnect`、`attach` を登録する。`PS4.begin()` の引数・ペアリングは維持する。
入力コールバック前にライブラリが生値をコピーするため、その時点の値を通知する。
接続/切断通知では古い入力値を読まない。

このバージョンの `ps4.c` は切断時に公開コールバックを呼ばず、最初の入力パケットも
接続通知だけに置き換えていた。`scripts/patch_ps4_notifications.py` をPlatformIOの
preスクリプトで適用し、切断の一度だけの通知と、接続通知に続く最初の入力通知を補う。
バージョンを固定し、既知の関数本文だけを変更する。未知の実装では書換えずビルドを失敗させる。
再実行可能。Bluetooth設定・アドレス・制御値は変更しない。
ライブラリ既存の接続コールバック前250ms待機は残るため、即時応答の保証ではない。

## 所有と優先順位

コールバックは時刻・生入力とイベントを静的64件FIFOにコピーするだけ。
短いportMUX区間で保護し、領域待ち・動的確保・ログ・指令実行を行わない。
制御ループがまとめて取り出して既存の操作処理へ渡す。
入力変化のないパケットは比較して省略し、押下/解放は別々のイベントとして残す。

×の実際の押下と切断はFIFO外にもラッチする。取り出し時に停止を先行させ、
それ以前の入力でShare/Optionsが再有効化・開始しないよう通番の境界で拒否する。
接続時のボタン解放・中立確認、FOC未完了の拒否、停止条件とボタン割り当ては維持する。
FOC完了以前の入力も観測するが、FOC完了後に遅れて開始指令として再生しない。

イベントが来ない間も最後の受理入力を保持して既存の50ms処理を呼び、速度/旋回ランプと
停止完了判定を継続する。保持入力から新しい押下エッジは生成しない。
入力通知の欠如を切断・中立・全停止の条件にはしない。

## あふれ

FIFOは上書きしない。満杯時にはあふれ回数、接続/切断回数、最新実測状態、
押下/解放の累積数と欠落したボタンのビットマスクを保持する。
×・切断・使用軸の実際の中立遷移も別ラッチで保持する。
中立遷移は従来の走行要求中の通常停止へ、切断は既存の走行要求解除へ渡す。
×が同時にあれば全停止を優先する。

有限領域なので、あふれた全イベントの順序・全ボタン操作を復元できるわけではない。
曖昧な指令は再生せず `QUEUE_OVERFLOW_REARM` として拒否し、あふれ後に届いた
実際の新規パケットで全ボタン解放・両スティック中立を確認して再同期する。
同じ中立データでも、この確認用の次の実パケットは省略しない。
あふれだけを新しい停止条件にはせず、既に受理済みの保持指令の更新は続ける。
停止ラッチはキュー容量に依存せず保持するが、実行は制御ループが再開した時点となる。
既存の同期FOC・校正中の停止応答は実機での確認が必要。

## 診断

Webは最新コピー、Serialは状態・入力・操作判定の変化時のみ送信する。
同じ入力パケットの受信数だけの増加ではSerialを出さない。送信間隔・バイト上限は維持する。
`sample_valid` は接続後に実際の入力を観測済みかを表す。
`sample_ms` は最後の変化/再同期サンプル時刻で、リンクの生存判定には使わない。
FIFO受信/同一省略/あふれ、押下/解放回数と欠落マスクを表示する。
マスクはbit0から Cross, Circle, Square, Triangle, Up, Down, Left, Right,
L1, R1, Options, Share, PS の順。全履歴は保存しない。

## 検証範囲

`python3 tests/ps4_events_host/run.py` は実ライブラリの公開APIと通知関数をコンパイルし、
接続→最初の入力、切断の重複抑止、再接続、パッチの再実行/未知本文拒否、
FIFO順序・同一入力・あふれラッチ・並行生産者を確認する。
`python3 tests/drive_host/run.py` は実際の制御側関数を使い、短い押下/解放、
スティック保持、通常停止、再接続、停止優先、FOC境界、あふれ/中立再同期を確認する。

ホストテストとビルドは、実機のBluetooth接続・HTTP起動・制御周期・停止遅延の証明ではない。
今回のイベント方式、静止倒立、走行/減速/停止、旋回、脚操作は実機未検証。
ユーザーによる以前のFULL静止自立確認と、今回変更後の実機確認を区別する。

HID送信の確保失敗・接続途中の中断処理と、その版固定/全体SHA照合パッチは
[PS4 L2CAP確保失敗](ps4-l2cap-allocation.md)を参照。
既存の操作/停止経路と通知FIFOのサイズは変更していない。
