# 姿勢専用グラフ・左右指令メーターと起動後倒立

基準: `codex/2208-web-ps4` / `2867913` と取得した先頭の一致を確認。
PR #13の基準ブランチは `codex/2208-short-drive` / `dfd4d0c`。
画面・配信の変更と、自動開始の変更は別コミットにする。

## 姿勢・出力の画面

- 上段は姿勢角／基準角の専用グラフと、左に左出力・右に右出力メーター。
- 姿勢軸は常に−30°～＋30°。中央0°線を明示し、線は枠内でクリップ。
  超過時は▲／▼と実際の角度を数値表示。表示範囲は制御の開始／転倒閾値ではない。
- メーターは真上0 V、正は青・時計回り、負は赤紫・反時計回り。
  ±1 Vでそれぞれ半周、0は弧なし。上限超過は弧を半周まで描き、実数値と警告を表示。
  小さい非ゼロ値を0として表示しない。遮断は灰色「遮断」、配信／通信停止・無効・古い値は「更新停止／不明」。
- 値は既存の制限・旋回・安全判定後のmove直前の**指令電圧**。
  FOC q電圧・電流・トルクではない。停止時の既存ゼロ指令も観測キャッシュに反映。
- 補助グラフは独立して折りたためる。姿勢・補助は共通の取得時刻／60秒の表示期間。
  単位別補助軸・固定色・凡例切替・補助軸自動範囲は維持。姿勢軸は自動範囲対象外。
- 表示一時停止は両グラフだけを止め、メーター・状態・受信／履歴保持は続ける。
  項目選択・詳細・CSVは下部の折りたたみ。姿勢角は既存相補フィルター後、追加フィルターなし。

## 測定の鮮度

既存の `mpu6050.update()` 後に `updateLqrState()` が読んだAngleY／GyroYを
`noteImuMeasurement()` で時刻imu_ms・連番imu_seqへ記録する。新規I2C読み取りなし。
正常初期化後の停止／待機でも、この既存ループを継続する。
通信側は追加I2Cも安全ゲート解除も行わない。

sample_msは制御状態コピー時刻で、IMU実測時刻ではない。
実測が更新されなければimu_ms／imu_seqは変えない。
初期化前、校正中、未取得、左右車輪異常によるループ停止、非有限値、250 ms超の測定停止を
imu_reason／imu_validで区別し、姿勢・角速度・誤差をnullにする。
通信タスクも送信直前に時刻だけを検査し、制御ループが止まっていても無効化する。
受信が続いても、古い測定に新しい実測時刻を付けない。

指令もcommand_ms／command_validで既存の設定／最終指令更新時刻を追跡する。
250 ms超の古い指令を現在出力に見せない。ブラウザーは受信停止300 ms超も検知
（100 ms周期で表示更新するため最大約400 ms）。診断配信停止・切断時は即座に不明表示。
基準角は設定値としてreference_validを別表示する。測定無効区間は姿勢線を切り、0で補わない。

## 状態・配信

stateはINITIALIZING／READY_WAIT／BALANCE_WAIT／BALANCING／EXPLICIT_STOP／FALL_STOP／
FAULT／STARTUP_FAILED／AUTO_WAITの名前で表示。起動段階startup_reasonと最新停止理由・時刻は別。
異常bitに加えて右／左の既存センサーerror名を表示する。
起動段階・失敗フラグ・校正フラグはatomic、制御snapshotは既存の短い排他でコピー。
通信タスクから制御変数やI2Cを直接操作しない。

常設4項目＝angle_deg／reference_deg／right_command_v／left_command_v。
subscribe要求にサーバー側でも常設maskを追加する。ACKは常設＋受理した任意項目を返す。
補助線の初期選択はgyro_deg_sのみ。任意項目は選択したものだけ送る。
電圧は常設配信だが、補助の電圧時系列線は別途チェックで選択できる。
補助を全解除しても常設4項目は継続する（空subscribeは送らない）。
200 ms集約、古いACKの除外、受理待ち1件、有限失敗・無限再試行なしは維持。
「配信停止」は既存stop JSONで測定配信だけを止め、状態のみ1 Hzで継続。
停止中のチェック変更では再開しない。「配信開始」で診断配信だけを再開。
Webからの走行指令／PID設定を追加せず、Web切断を走行停止条件にしない。

WebSocket 1クライアント・20 Hz、ブラウザー履歴60秒／1200点、既存送信期限／WDT対策、
スタック・PS4 FIFO/Batchは維持。機体側の長い履歴は再導入しない。
HTML→style.css→panels.css→signals.js→history.js→plot.js→subscribe.js→dashboard.js→app.js
を本文完了順で直列取得する。全ファイルはLF／CRLFとも8 KiB以内。

## 起動後の自動倒立（画面とは別コミット）

**このファームは自動倒立が有効。正常初期化後、開始操作なしで倒立へ移る。**
既存の校正・左右FOCアラインメント中の動きは、通常倒立開始とは別で従来どおり発生する。

BootAutoStartは起動ごと1回の意図だけを保持する。正常な校正・両輪FOC・センサー・
既存Web起動前提が成立し、startup_foc_readyが確定した後に動く。
ブラウザー接続、WebSocket、購読、PS4接続は開始の追加条件にしない。
正常起動後のWi-Fi再接続待ちを、新たな自動開始条件にも停止条件にもしない。

基準角は未取得の0値をそのまま有効化しない。既存の手動開始は安定した任意の角度を
候補として基準取得できるため、自動開始だけは追加の**重力基準0°から±2°以内**に限定。
これは既存 `kBalanceWaitAngleLimitDeg=2` を再利用した起動時の姿勢制約。
既存の角速度開始上限2 deg/s、平均車輪速度0.8 rad/s、安定保持1500 msも再利用する。
正しい取付方向で、既存相補フィルターの重力基準0°が直立付近であることを実機で確認する。
傾いた起動姿勢を無条件で直立基準に登録しない。

条件を連続1500 ms満たすと、`executeOperatorCommand(Start)` → `startBalanceTest()` の
既存経路へ一度だけ入る。最初は倒立ではなく、既存2秒準備＋1500 ms安定保持の基準取得待ち。
この間も自動開始だけは絶対姿勢／角速度／速度の上記条件を継続確認し、外れたら保持計測をリセット。
範囲内の実測平均でangle_zeropoint／distance_zeropointが取得され、lqr_zero_set=trueに
なった後でだけ、既存処理がlqr_direction_test_armed=trueにする。最短でも概ね5秒。
準備中に外れた場合、準備の2秒を延ばすのではなく、既存の保持計測をやり直す。

通常運転のPID・検証済み符号・FOC・フィルター・転倒／異常停止条件、手動開始の判定式は不変。
**開始モードも既存のままで、初期値はATTITUDE_ONLY**。自動でFULLに変更しない。
FULL等のモード変更とPS4再開始は既存手順で行う。起動時自動開始を止めてからモードを操作する。

明示停止（待機中も含む）、転倒／異常記録、既存の手動開始・直接操作が優先されると
起動時の自動意図を解除する。停止後の自動再試行・自動再始動なし。
PS4×の全停止・既存再有効化・手動再開始は維持する。
転倒後の冗長なSTOPで、既存の転倒理由を手動停止に上書きしない。
