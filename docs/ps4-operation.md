# PS4操作と検証範囲

## 基準と制御変更

基準ブランチは `codex/2208-short-drive`、基準コミットは `dfd4d0c`
（Test balance feedback signs and lower position gain）。
速度P=0.25、位置P=0.1を保持する。FULLの位置項、FULL / ATTITUDE+SPEEDの
速度項の反転も保持する。PID、FOC、電圧上限、転倒判定、PS4ホストMACは変更しない。

実装前に提示し、利用者の承認を得た変更：

```text
speed_control = pid_speed(target_speed - measured_speed)
通常のFULL / ATTITUDE+SPEED: speed_direct_term = -speed_control
旧ソフト停止:               speed_direct_term = +speed_control
修正後ソフト停止:           通常時のモード別符号をそのまま保持
```

旧ソフト停止の正符号による上書きを除去した。FULLの位置項は従来どおり反転する。
ATTITUDE+DISTANCEの速度・位置の扱いは変更しない。
PS4走行は既存の微小目標傾斜方式を保持し、直接速度項は既存設定どおり無効。
旋回は新規の左右差動電圧指令（最大±0.10V、50msごと最大0.01Vの変化）を加える。
既存の全体電圧上限1.0Vは変更せず、倒立の共通出力を優先する。

```text
common = clamp(test_LQR_u, -existing_limit, existing_limit)
headroom = existing_limit - abs(common)
yaw = clamp(yaw_command, -headroom, headroom)
right = (common - yaw) * right_forward_sign
left  = (common + yaw) * left_forward_sign
```

旋回は角速度の閉ループ制御ではない。旋回量・中立後の回転の収まり方は実機未検証。
傾き・速度・出力飽和などの既存走行安全判定を通し、復帰中は旋回を無効にする。
平均車輪速度だけでは純旋回の速度を十分表現できない点にも注意が必要。

## 操作一覧

| 操作 | 動作 | 条件・備考 |
|---|---|---|
| △を押す | モード切替 | シリアルg、Web modeと共通。停止状態・スティック中立時のみ |
| Optionsを押す | 静止倒立の開始要求 | シリアルt、Web startと共通の開始処理。既存の準備・安定判定後に開始 |
| 左スティックY | 前進・後退 | 既存割り当てを維持。上が前進。最大要求±0.05、既存の安定開始ゲート・目標速度スルー制限を使用 |
| 右スティックX | 左右旋回 | 右が右旋回の指令。前後進と併用可。単独旋回も同じ開始ゲートを使用 |
| 使用するスティックを中立へ戻す | 走行停止要求 | 倒立を継続。保留中の開始要求は取消。走行中は既存のソフト停止へ移行 |
| 十字キー上・下 | 両脚を10%刻みで上下 | 既存割り当て・0～30%の範囲を維持。押下エッジ1回に1段。準備・走行・減速・復帰・無効化中は拒否 |
| × | 明示的な全停止 | シリアルdと共通。倒立OFF・車輪ドライバー無効化・既存方針どおり脚トルクOFF |
| Shareを押す | 車輪ドライバー再有効化 | シリアルuと共通。停止状態・スティック中立時のみ。指令はゼロ、倒立は開始しない |

全停止後の再開始は「全入力を解放 → Share → 解放 → Options」。
転倒・センサー異常時はまず原因と状態を確認する。初期化未完了なら再有効化を拒否する。
全停止の×は接続直後の押しっぱなしでも停止を優先する。

ATTITUDE ONLYは既存どおり走行不可。確認済みのFULLでの開始を推奨する。
モードの起動時初期値は既存どおりATTITUDE ONLY。停止状態で△を1回押してFULLを選び、
状態表示またはシリアルで確認後にOptionsを押す。これでPS4だけで一連の操作ができる。
Optionsでモードを勝手に変更しない。
スティックの値が±10以内なら中立と扱う。
接続後は全ボタン解放・両スティック中立の受信が必要。
開始操作は押下エッジだけ受け付け、押し続けても準備を再開始しない。
倒立開始前からスティックが倒されていた場合、開始後に一度中立へ戻すまで走行しない。
再接続でも同じ解放・中立確認を必要とし、接続だけでは倒立・走行しない。
切断時は前後進・旋回要求を解除し、保留開始を取消、走行中はソフト停止を要求する。
既存方針に合わせ、切断だけでは倒立と脚保持トルクを切らない。
切断前のシリアル由来の走行要求も解除する。通信断の検出時間自体はPS4ライブラリに依存する。

## 既存操作と共通経路

整理前：PS4は左スティックYによる走行、十字キー上下による脚操作を実装済み。
開始・旋回・明示的な全停止のボタン割り当てはなく、他のボタンは診断表示のみだった。
シリアルはtで開始、>/<で自動短距離走行、.でソフト停止、eで走行のみ停止・倒立復帰、
dで全停止、uでゼロ指令の再有効化。Webは開始・終了・モード/速度源切替とCSV取得を担当。

整理後：`executeOperatorCommand` が開始・試験終了・全停止・ソフト停止・再有効化・
脚操作を振り分ける。PS4、シリアル、Webは既存の `startBalanceTest`、
`requestLqrDrive`、`requestLqrSoftStop`、`stopBalanceTest` と状態遷移を共有する。
全停止ではログ出力の前に車輪出力を遮断する。
シリアルの直接電圧試験、ゼロ点取得、診断、脚の個別操作なども残す。
シリアルのs/0は従来の電圧目標ゼロであり、倒立中の全停止にはdを使う。
シリアルのeは従来の走行のみ停止・姿勢復帰処理を維持する。
Web STOP TESTは既存の試験終了であり、PS4の×/シリアルdのドライバー無効化とは異なる。

Webの役割・API・ファームとdataの書き込みは [web-files.md](web-files.md) を参照。
Webの受付はHTTPタスク、指令実行は制御ループが担当する。
通常走行の停止では倒立を維持し、全停止は明示操作・実転倒・既存の異常停止方針で行う。
新規の旋回実出力はLQR control CSVのright_output/left_outputで確認する。
既存の走行符号・停止用シリアルトレースが再構成する左右出力は共通倒立出力であり、旋回差分を含まない。

## 検証と実機未検証

- 利用者確認済み：`dfd4d0c` のFULLで接触なしの静止自立。
- 本変更後：静止倒立、前進・後退、減速・停止、旋回、脚操作を実機では試験していない。
- ホスト検証：実際のC++関数を抽出してコンパイルし、解放・中立、接続/切断/再接続、
  押しっぱなし、開始待ちからの中立、保留取消、開始拒否時の状態保持、左右走行、
  ソフト停止の符号、旋回の電圧余裕・左右反転、全停止と再有効化、脚の上下限を確認する。
- 既存の開始ゲート・復帰・転倒停止・センサー異常・転倒後CSV保持・停止理由も回帰検証する。
- ESP32ファームとLittleFSイメージのビルドを実行する。ビルド成功・ホストテスト成功は
  実機の安定性や制動性能を保証しない。

実機評価ではまず変更後FULLの静止倒立を再確認し、保持・停止手段を確保した状態で、
前後進それぞれの中立停止、切断時の減速、全停止、旋回単独/併用、脚操作を段階的に確認する必要がある。
低速HTTP/CSVクライアント併用時の最大制御周期・メモリー残量も計測が必要。
C3・レーザー・音声は対象外。既存PRのマージと実機への書き込みは行わない。

ペアリング初期化は基準版の引数なし `PS4.begin()` をそのまま維持する。
コメント内のホストMAC指定の再有効化やアドレス変更は行っていない。
