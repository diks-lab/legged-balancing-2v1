# PS4操作と検証範囲

基準9c6b2e6。機体の基本操作はPS4、Webは状態・診断配信と既存の明示校正用。
今回の変更は入力割当と再操作ゲートで、車輪PID・FULL・DLPF・保存FOC・方向係数・
脚の実測換算／受付／端余裕／通常範囲・速度／旋回上限・加減速／ブレーキは変更しない。
左車輪不動の調査・解決は今回の対象外。実機の新割当は未検証。

## 操作一覧

| 入力 | 動作 |
|---|---|
| 左スティック上／下 | 脚の伸長／短縮。中央で高さ指令保持 |
| 左スティック左／右 | 左／右傾斜の目標操作。ただし方向未確認のため無効 |
| 右スティック上／下 | 前進／後退。右中央で既存の減速・停止 |
| 右スティック左／右 | 既存旋回。前後進との斜め入力も従来の制限内 |
| 十字キー | 予約。脚・走行・その他の指令を発生しない |
| × | 支持試験で使う既存の全停止・脚OFF。今回、通常運用の新しい停止仕様は追加しない |
| Share | 停止・全解放後の既存ドライバー有効化。脚移動・倒立開始はしない |
| Options | 既存の手動倒立開始経路。押しっぱなし・接続だけでは開始しない |
| △ | 停止中の既存モード切替。通常起動／転倒復帰の基本モードはFULL |
| その他 | 既存の観測／未割当。新たな機能を追加しない |

十字キーは操作開始のボタン解放判定からも外す。十字の押下／解放だけで、
脚同期・走行開始・中立停止が起きない。生ボタン状態・押下／解放イベントの観測自体は残す。

## 左の比例操作と再操作ゲート

設定は`include/Ps4ControlMapping.h`。各左軸の絶対値16以下は指令0。
外側は`(絶対値−16)/(最大絶対値−16)`で0～1へ連続変換する。
符号付き端点−128／+127を各最大値として、上＝LY負を伸長、左＝LX負を左傾斜目標正とする。
高さは最大4ポイント/秒、傾斜は最大2°/秒・目標±3°。入力通知回数ではなく実経過時間で変化する。
中央で高さを保持し、確認済みの場合の左右目標は従来の速度で0°へ戻す。

中央復帰の確認は動作DZより狭い**左XY両軸±10**。
11～16では指令0だが、停止等からの再操作許可を得ない。17付近の揺れが同期再開始を繰り返さない。
接続直後は既存のボタン解放と両スティック中央を確認してから、次の操作を受ける。

`LEG_ROLL_DIRECTION_CONFIRMED=0`を維持する。左Xだけで脚を同期・ONしない。
一度左中央を確認済みならXを倒したままYを加えて上下のみ操作できる。
再操作が必要な場合は、左右が無効でもXを含む両軸を中央へ戻す。
左右要求は表示し、実際の左右適用入力・AngleX補正は0とする。

初回は既存の左右読取り→取得tick完全一致プリロード→ONを使う。
通常範囲外なら保持のみで、左中央→新しい内向き倒し込みから戻す。
最縮余裕外は上、伸長側は下。左右差、矛盾時停止、片側が端での両側停止は維持する。
[実測値・範囲と手順](ps4-leg-control.md)を参照。

## 右の走行入力・競合

前後入力の取得・速度要求・中央・開始・減速／停止・切断・古い入力破棄をすべて右Yへ移した。
右Xは従来どおり旋回。右のDZ±10、最大速度0.05 m/s、旋回上限0.10 V、
50 msごとの速度目標変化0.02 m/s／旋回変化0.01 V、既存プロファイルを維持する。
入力の変換は従来の走行式であり、左脚用の新しい比例曲線を右に持ち込まない。
旋回は倒立共通出力の残余電圧だけを使う。FULL等の既存走行可能モードを変更しない。

同時入力は右優先。右入力・走行／減速中は脚の増減・補正を止め、既存位置を保持する。
右が中央へ戻って走行が終了しても、倒しっぱなしの左は再開しない。
左XY中央→新しい操作で、改めて位置同期する。
支持試験では右だけで倒立・走行を開始せず、右入力中は脚も保持する。

切断は走行要求を解除し、車輪の既存停止方針を使う。
脚は未送信の増分を破棄して最後の送信指令を保持し、同期途中ならプリロード／ONを中断する。
再接続、×停止、転倒復帰、通信失敗、FIFOあふれ後の古い倒し込みを再開しない。
FIFOの中立遷移保持も右XYへ移し、左操作を車輪の中立停止通知として扱わない。

## 診断・実機確認

生LX／LY／RX／RY、左正規化要求、ゲート後の脚適用、右速度／旋回要求を分ける。
Webは下部「脚入力・許可判定」、シリアルは固定長記録からの変化時出力を使う。
要求の適用欄はプロファイル・最終制限前で、実際の位置・速度・電圧出力とは区別する。
PS4の一般decisionは入力経路の受付を表す。脚の可否は同周期の確定状態・拒否理由と適用欄で確認する。
同じ入力の保持通知・周期的な時刻更新だけではシリアル出力を増やさない。
未接続・通信停止時は最終受信情報と表示する。ペアリング設定・公開コールバックAPI・FIFO容量は不変。

更新はファーム＋LittleFS両方。実機書込み・マージは本作業で行わない。
機体を支持して外部電源コードの非干渉を確認し、×→両スティック中央・ボタン解放→Share→解放。
左Yの微小／半分／最大・中央保持、左Xのみ拒否と斜めの上下、十字無出力を先に確認する。
次に通常外の保持・中央・戻し、切断／再接続・停止後の倒しっぱなし拒否を確認する。
支持中に右だけで倒立開始しないことを確認してから、静止倒立中の脚操作、
最後に安全を確保して右の前後・旋回・中立減速と、終了後の左中央待ちを確認する。

旧割当と過去の調査記録は[旧版履歴](history/ps4-operation-before-stick-remap.md)に保存した。
車輪の静止調整との比較は[現行と静止調整版](full-mode-baseline.md)を参照。

## 検証結果・資源（9c6b2e6比）

全21組のホスト回帰、脚・走行・配信ASan/UBSan、実Chromium＋模擬JSON
（1366×768／1920×1080、100%）、ESP32ビルド、LittleFS生成が成功した。
実際の公開コールバック→FIFO→制御処理で、十字全方向無出力、左だけ脚／右だけ走行、
半倒し2 pp/s・最大入力・微小入力・斜め・保持通知なし・中央復帰、支持試験右入力の開始禁止、
走行優先と終了後中央待ち、同期中切断・再接続・×・FOC入力バリア・転倒復帰・車輪通信失敗、
CRC失敗後の倒しっぱなし拒否、範囲外の完全一致保持・内向き戻し・矛盾・片側端を確認した。
単体試験で中心10／動作16の帯域、時間基準速度、無効左右要求の上下のみ受理、
古い生値観測から指令を再生しないこと、同一状態のシリアル非反復を確認した。
実機での新割当、脚動作・走行／減速、左右旋回の成功は未検証。

静的RAM83,676→83,780 B（+104 B）、Flash1,935,837→1,938,269 B（+2,432 B）。
StickObservation36 B、Control400→444 B、State384→420 B、Snapshot1000→1036 B、
シリアル記録器620→644 B。内包関係があるため合算しない。
イベント72 B×8、出力器280 B（192 B整形領域を内包）、UARTバス140 B、
PS4 FIFO／Batch容量・スタック設定・WSオブジェクト3192 B／送信容量2048 Bは不変。
最大詳細JSONは1734→1804 B（+70 B）、追加は1 Hz診断で20 Hz選択サンプルは変更しない。
局所Snapshotコピーは36 B増える。実機の起動ヒープ・制御時間への差は未測定。
