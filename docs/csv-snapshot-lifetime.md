# CSVコピーの必要時確保

元の5種類のトレース配列（計28,208 B）、転倒後ログ・停止イベント、記録/リセット条件は維持する。
HTTP状態キュー、PS4 FIFO/Batch、スタック、PID/FOC/操作/停止条件も変更しない。

以前は `HttpTraceSnapshot` 10,776 Bを内部DRAMに常駐させていた。
現在は取得要求ごとにHTTPタスクが同サイズのunion/件数/インデックスを一つ確保する。
制御側は要求された種類の配列と管理情報をコピーするだけで、確保/解放しない。
要求公開前にポインターと種類を設定し、atomicの公開/取得で順序付ける。
同期WebServerは同時に一つのハンドラーを実行する。

| 状態 | 制御側 | HTTP側の終了処理 |
|---|---|---|
| Idle | 触らない | コピーなし |
| Requested | CASでCopyingへ進んだ場合だけ使用する | CASでIdleへ取り消せた場合は即解放 |
| Copying | 既存の走行中判定、許可時のみ固定長コピー | タイムアウト/切断時も解放せず保留 |
| Ready | 完了公開後はポインターに触らない | 送信後、または保留要求の回収時に解放 |
| Busy | 従来の走行中拒否。公開後は触らない | 409応答後、または回収時に解放 |

制御側の完了通知が出るまで、保留領域のポインター/種類を変更しない。
HTTPタスクの通常処理と次のCSV要求の入口で、完了した保留領域を回収する。
Wi-Fi切断でクライアント処理をしない間も回収処理は動く。
制御側が再開しない場合は解放せず最大1領域を保持し、追加要求は503で拒否する。
これは使用中メモリーの解放を避けるための仕様で、待機中に領域を追加確保しない。

コピーは開始前の既存安全ゲートを通る。コピー取得後に試験が再開始されて元配列が
リセット/更新されても、送信は独立コピーから続ける。送信内容は変化しない。
成功・空ログ・走行中拒否・確保失敗・送信中切断の全return経路をRAIIで終了処理する。
確保失敗は503、コピー待機500ms超過/前のコピー保留も503。元ログを消去しない。
確保はHTTPタスクのmalloc、解放は同じHTTPタスクのfreeのみ。
コピー本体は最大10,752 Bで、送信を制御ループへ移すことはない。

## 通常ログと詳細診断

`HTTP_MEMORY_STAGE_DIAGNOSTICS` のソース既定値は **0/OFF**。
必要な場合だけ `platformio.ini` の `[env:esp32dev]` にある `build_flags` に追加する：

```ini
build_flags = -DHTTP_MEMORY_STAGE_DIAGNOSTICS=1
```

OFFでも起動結果・失敗箇所、Wi-Fi接続完了時のIPと数値URL、
起動正常確定/失敗報告時の `STARTUP memory result=... heap_free=... internal_free=... internal_largest=...`
を出力する。タイムアウト後の待機で同じ失敗ログを周期出力しない。
既存の接続復旧と一度だけの起動メニューは維持する。
ONでは従来の段階別 `HTTP memory stage` も表示する。
`trace_copy_request_bytes` は取得時に要求するサイズで、常駐コピー領域を意味しない。
状態APIのメモリー情報は設定によらず残す。

## 検証

`tests/drive_host/run.py` は実CSV処理をコンパイルし、3種の確保失敗503、未取得要求の
タイムアウト/切断取消、別スレッドでCopying中のタイムアウト/切断と追加要求拒否、
完了後の回収、送信途中の実際の試験再開始、送信中切断、30周×3種の連続取得を確認する。
各終了後の確保/解放回数を検査し、元ログと停止記録の保持を既存の回帰試験でも確認する。

`ASAN_OPTIONS=detect_leaks=0 CSV_TEST_SANITIZERS=1 python3 tests/drive_host/run.py`
でもAddressSanitizer/UBSanを実行する。この実行環境ではLeakSanitizerがptrace制約により
使用できないため無効化し、CSV領域の未解放は専用の確保/解放カウンターで確認する。
`tests/http_startup_host/run.py` は診断設定0/1の両方をコンパイルし、通常時の詳細抑止、
READY/タイムアウト時の最終残量、IP/URL、一度だけのメニューを確認する。

ビルドの静的RAM減少と、実機のWi-Fi接続/内部ヒープ残量は別の結果である。
取得時には10,776 Bとアロケーター管理分の空きが必要で、確保できない環境ではCSVが503となる。
Wi-Fi接続成功・低速通信時の制御周期・実機停止応答は書き込み後の別途確認が必要。
