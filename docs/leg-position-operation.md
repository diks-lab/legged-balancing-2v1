# 脚の位置操作・HOME中立復帰・走行併用

基準33be645。AGENTS.md、upstream-origin.md、脚・診断関連文書を確認。
作業中に追加された仕様を統合し、旧「上下中立で高さ保持」「通常走行で脚を凍結」は差し替えた。
利用者が選んだ通常高さHOMEは、左右の通常操作範囲の共通部分の中間。
現在の保存4点では約16.512%（約16.5%）。既存の最縮側手動HOMEとは別で、校正値は変更しない。
%はサーボ可動量の比率で、機体高さや脚長への比例は保証しない。

## 実装仕様

| 入力 | 指令 |
|---|---|
| 左Y正／負 | HOMEより高い背伸び／低いしゃがみの位置目標 |
| 左Y中立 | 明示的な上下操作後はHOMEへ戻す |
| 左X負／正 | 左正／右負の傾斜角目標。最大±3° |
| 左X中立 | 目標角0°へ戻す |
| 右Y／右X | 既存の速度／旋回。符号・上限・加減速は変更しない |
| 十字キー | 予約。脚・車輪へ指令を出さない |

上下・左右とも倒し量による位置目標であり、保持時間で目標を積算しない。
小さい正の入力へ戻したときは、現在位置より低い背伸び目標へ動く場合がある。
画面の「背伸び目標／しゃがみ目標」はHOMEに対する要求で、実際の移動方向の断定ではない。

`LegControl.h`の主な設定：

- 動作DZ±16、再操作中央確認±10は従来どおり。
- DZ外を0～1へ正規化し、`f(x)=0.5*x+0.5*x^3`を適用。
  `HeightCurveBlend` / `RollCurveBlend`は各0.5。中央寄りは穏やか、端では従来と同じ最大値。
  正規化50%入力では31.25%の目標変位になる。
- `HomeRangeFraction=0.5`。HOMEは左右の通常範囲の共通部分の中間。
  上下目標はHOMEから上下端までの変位にカーブ後入力を掛ける。
- 高さの目標追従は最大12ポイント/秒。
- 左右差は最大8ポイント/秒、P=3。
  目標角追従・中立復帰は`RollRate=8/P=約2.67°/秒`。
  P×目標変化速度を左右差速度へ揃え、遅い積算指令を重ねない。
- 最大入力から中立への目標復帰は理想条件で上下・左右とも約1.1秒。
  左右の最大反対側への切返しは約2.25秒。速度制限に由来し、待機タイマーは追加していない。
- 整数化ヒステリシス、50ms送信、サーボ速度150・加速度15を維持。
  目標は速度制限で連続変化し、余計な往復を抑える。表示用・IMU用の新しいフィルターはない。
  サーボ内部の動作や実機での「小刻み」が解消したという確認ではない。

## 開始・範囲・異常時

起動・同期だけでHOME移動や姿勢補正を始めない。
初回READ→取得tick完全一致プリロード→ONを維持し、その後の明示入力から追従する。
上下操作をまだ開始していないときは、左右操作だけで高さをHOMEへ動かさない。
範囲外では取得位置を保持し、中央確認後の新しい内向き上下操作だけを許可。
この間は中立でHOMEへ自動移動せず、左右操作・姿勢補正もしない。
左右の必要方向が矛盾すれば移動せず、片側の進行端では両脚を止める。
通常範囲・10tick余裕・保存4点・左右差の保持を維持する。
傾斜余裕を作るためだけに高さを変えず、既存の範囲保護で傾斜要求を制限する。

通常の走行・減速中は脚操作を受け付け、走行終了だけでは再同期しない。
右操作だけで、支持試験の車輪を倒立・走行開始させない。
転倒・明示停止・異常では既存の停止／遮断処理を維持。
車輪の保護復帰・センサー再試行中は脚を停止／保持し、左中央・新操作から再開する。
切断時はHOMEへ自動移動せず、最終送信位置を保持し、旧入力を再接続後に再開しない。

## 実機確認：操作感だけで評価する

外部電源コードを脚・車輪から離す。バッテリー改造は前提にしない。
通常はログを取らず、各項目を「遅い／速すぎる／ちょうどよい」「滑らか／小刻み」で評価する。
異常時だけWebの理由または既存`:leg status`を確認する。詳細ログは既定OFFのまま。

### 1. 支持状態の脚操作

1. 機体を支持し、×→全中央・解放→Share→解放で支持試験へ入る。
2. 初回は取得位置の保持を確認。範囲外なら上下だけで通常範囲へ戻す。
3. 上下を**少し→中立、半分→中立、大きく→中立**。上／下の両方向でHOMEへ戻ることを見る。
4. 左右も**少し→中立、半分→中立、大きく→中立**。両方向で0°目標へ戻ることを見る。
5. 動作開始・切返し・中立復帰を分けて、速度感と小刻みの有無を記録する。
   中立直後は移動が続き得る。入力終了を到達完了と扱わない。

### 2. 低速で同時操作

1. 既存の倒立開始手順（支持試験からは全中央・解放後のOptions）で静止倒立を先に確認する。
2. 右を少し倒した低速で、左の上下・左右をそれぞれ少し→中立から試す。
3. 車輪の走行・旋回と脚操作が両方継続し、右中立の減速中も脚が使えることを確認する。
   切返し・停止・異常時の動作も低速で確認する。

### 3. 速度を上げた操作

低速段階が良好な場合だけ、既存の許可速度内で右を段階的に大きく倒し、同じ左操作を比較する。
車輪速度上限0.05m/s・旋回上限0.10V・車輪PIDは今回変更しない。
各段階の脚操作感だけでなく、倒立振動・姿勢・走行／停止の安定性を確認する。
支持状態の成功だけで、走行併用・高速安定性まで完了としない。

## ソフト検証と更新

ホスト回帰23組、脚／UART／NVS／実PS4制御／配信のASan/UBSan、ESP32／LittleFSビルドが成功。
1/2/5/10/20/50ms周期でカーブ・目標保持・HOME/0°復帰・切返し・速度上限・範囲を確認。
実PS4コールバック→FIFO→制御→UARTで上下／左右・斜め入力・初回完全一致・範囲外・
切断／再接続・停止・保護復帰を確認。3段階の右速度要求／旋回と脚を同時処理し、
非同期READ継続・余分なONなし・Web状態との一致を確認した。実機の速度試験ではない。
Chromium＋模擬データで1366×768／1920×1080と125%相当、更新した説明・状態表示を確認。

33be645比：静的RAM84,764→84,772B（+8B）、Flash1,955,309→1,955,481B（+172B）。
Control572→576B、State548B／Snapshot1164B／ServoBus148Bは不変。
新しい履歴・診断項目・常時出力・タスク・待機を追加しない。
UART最大16RXバイト・1TX/サービス、50ms位置送信・左右交互500ms READ、PS4 FIFO・スタックは維持する。
実機の制御周期や操作感・低速併用・速度を上げた際の安定性は未検証。
