# 転倒停止から直立範囲への進入周期で復帰

> 通常起動は [起立待ち](upright-start-wait.md) に更新。初期化後すぐの範囲外駆動は行わず、
> 0°±2°へ入った周期で開始する。時間・静止待ちは追加しない。


基準先頭2629b1a、codex/2208-web-ps4、PR #13。
**転倒後、最新の有効な姿勢が0°±2°へ入った最初の制御周期で倒立へ復帰する。**
完全一致0°、1500 ms保持、低角速度・低車輪速度の待機は要求しない。
範囲は両端を含む。新しいフィルター・デッドバンド・接地判定は追加しない。

## 判定と状態

確認済みの転倒停止だけが復帰意図を立てる。次の全条件を確認する。

1. IMU初期化・校正成功、既存読取り成功、有効かつ250 ms以内の最新有限姿勢・角速度。
2. 両輪センサー正常、位置・速度が有限。速度の大小では待たない。
3. 保存校正有効、両輪FOC ready、既存の必須初期化／ドライバー正常、校正中でない。
4. 姿勢が固定目標0°±2°以内。

角速度・車輪速度は大きくても有限なら静止待ちしない。
無効／古い測定・センサー異常・FOC異常では復帰意図を解除し、回復だけで再始動しない。
明示停止も意図解除。新たな確認済み転倒なら改めて復帰対象になる。
範囲外から範囲外へ測定間隔中に通過した可能性を、ソフトで補間して開始することはない。

復帰時は既存の制御状態リセットを共用し、目標角0°・復帰時の車輪位置原点を設定。
転倒／異常判定は復帰直後も従来の閾値・連続確認条件を維持する。
通常起動の即時開始、保存校正／明示校正、右−1／左＋1、PID、FOC設定、PS4操作・起動モード、
通信方式・期限・要求解析WDT対策・FIFO／スタック・長期履歴なしは維持する。

## 固定表示

上部に「直立範囲」「IMU」「車輪センサー」「FOC」を固定順で同時表示する。
制御側の同一関数で判定したrecovery_checksのbit0～3をJSONメタデータへ追加。
成立は緑の○、不成立は消灯相当の背景と×、通信／取得が古い・不明なら？。
直立範囲には現在の姿勢角と±2°も表示する。IMU無効時は角度不明。

制御状態（倒立中／転倒復帰待ち／明示停止／異常）は独立したラベル。
細かい復帰理由・センサー原因は下部詳細へ移し、上部説明を高速に切り替えない。
4条件の成立表示は開始指令ではない。明示停止中に条件が揃っても復帰しない。
停止履歴は別に保持し、復帰後は倒立中を表示する。

表示処理をstatus.jsへ分離し、10ファイルを既存方式で直列取得。
HTML/CSS/JSは読みやすい改行・インデントを維持し、LF／CRLFとも8 KiB以内。
最大はindex.htmlのLF 8,006 B／CRLF 8,144 B。
姿勢グラフ、左右ドーナツ、補助グラフ、凡例、配信操作は通常表示でスクロール不要。

## 検証

ホストの実制御関数：2.01°で未復帰、1.9°で時間を進めず同周期に復帰。
大きい角速度20 deg/s・速度10 rad/sでも静止待ちなし。±2°両端、非ゼロ角を確認。
範囲を1サンプルで通過する場合、範囲内測定がない場合、無効／古い／失敗IMU、明示停止、
保存校正不成立・FOC異常、復帰直後の再転倒、目標0°・位置原点・停止履歴分離を回帰。
既存の正常起動・PS4・保存校正・FOC・HTTP／WS回帰、制御ASan/UBSanも実施。

実Chromium＋模擬JSON：1366×768／1920×1080・100%でスクロール不要。
4ラベル同時表示、記号と色、境界進入・無効・古い値、明示停止／異常状態、詳細欄、
既存グラフ・メーター・凡例・配信選択・直列取得／失敗表示を確認。
**ビルド・ホスト・模擬ブラウザー試験を実機成功とは扱わない。**
実機の即時復帰、回復後の姿勢制御・再転倒／停止、振動、Wi-Fi／PS4併用は未検証。
強い振動は未解決で、表示を平滑化して隠していない。

**これは転倒からの再開動作であり、ジャンプ着地への対応ではない。**
接地検出・空中での制御・着地時の姿勢／車輪速度・衝撃応答は別途検証が必要。

## 資源・更新

ESP32ビルド・LittleFS生成で確認。固定JSON／送信バッファ容量は維持。
復帰タイマーを除去（12→8 B）、Snapshotは判定ビット追加と配置で380→384 B。
新たな長期履歴やタスクはない。status.js用HTTPルート1件の起動時確保が追加。

**ファームとLittleFSの両方を更新する。** 通常の書込みでは校正NVSを消去しない。

```sh
pio run -e esp32dev
pio run -e esp32dev -t buildfs
# 利用者が保持・対象ポートを確認して実施。エージェントは未実施。
pio run -e esp32dev -t upload --upload-port PORT
pio run -e esp32dev -t uploadfs --upload-port PORT
```

機体を確実に保持し、有効保存値で通常起動の即時開始を確認する。
転倒停止後、直立範囲へ戻すと保持時間なしに再駆動し得る。
復帰させない場合はPS4×等の明示停止を使う。マージ・実機書込みは行っていない。

ビルド比較（2629b1a→今回）：静的RAMは81,276 B→81,276 B、差0 B。
Flashは1,907,513 B→1,907,729 B（+216 B）。
JSONのrecovery_checksは通常21 B/sample（20 Hzで420 B/s、TCP/IP除外）増加。
固定JSON・WS・HTTP送信領域とタスクスタックは不変。新規HTTPルートの実ヒープ影響は実機未測定。
