# PS4脚操作・実測位置換算

現行の脚換算は脚専用NVSの有効な4点から生成する。未保存時は脚駆動だけを禁止し、
車輪初期化・起立／転倒復帰は従来どおり。旧測定値を暗黙に採用しない。
[4点校正・保存・最短登録手順](leg-range-calibration.md)を参照。
今回候補は右255回・左254回の正常取得、終了reason=NONEを利用者が物理端と確認したもの。
**10 tick余裕と新設定での駆動は実機未検証。左車輪不動・強い振動の改善を意味しない。**

## 座標と範囲

有効値はNVS `leg_range`。`include/LegGeometry.h`が換算・駆動範囲を生成する。
以下は今回の確定4点を明示保存した場合の値であり、未保存時の駆動用既定値ではない。
%はサーボ位置の実測可動量に対する割合であり、脚の実長・機体高さに比例するとは断定しない。

| 項目 | 右 ID1 | 左 ID2 |
|---|---:|---:|
| 実測最縮＝0% | 2044 tick | 2084 tick |
| 実測最伸＝100% | 1697 tick | 2408 tick |
| 可動量 | 347 tick | 324 tick |
| 伸長方向 | tick減少 | tick増加 |
| 初回受付（実測範囲全体） | 1697～2044 tick | 2084～2408 tick |
| 最縮／最伸からの暫定余裕 | 各10 tick | 各10 tick |
| 両端余裕の内側 | 1707～2034 tick | 2094～2398 tick |
| 通常駆動＝余裕内側∩0～30% | **1940～2034 tick** | **2094～2181 tick** |
| 通常駆動の実際の換算率 | 約2.882～29.971% | 約3.086～29.938% |

換算は `p=100×(tick−実測0%)/(実測100%−実測0%)`。
通常駆動の30%端は範囲外へ丸めず、右はtick切上げ、左は切下げで整数化する。
そのため通常端の実際の%は30%より少し内側になる。

四つの名前付き定数 `RightRetractedMarginTicks` / `RightExtendedMarginTicks` /
`LeftRetractedMarginTicks` / `LeftExtendedMarginTicks` を各10 tickとする。
根拠は、全可動量の約3%で1 tickの量子化より十分大きい、という暫定的な初回試験用の選定。
荷重時のたわみ、機構ストッパーや温度・バックラッシュに対する十分性は未確認である。
これを実測済み安全余裕と扱わない。サーボ内部の角度制限0～4095は書き換えない。

通常の位置指令は `leg::position()` に統一し、通常範囲内へ制限する。
手動HOME操作も**実測0%端ではなく余裕内側の最縮端**へ送る。
初回の現在位置プリロードだけは別経路で、実測受付範囲内の取得tickを一切丸めず使用する。

## 初回同期・保持・戻し操作

起動時に脚のHOME移動、位置指令、トルクONは行わない。
最初の明示的な上下操作から左右の現在位置56/57を非同期で読む。
ID・長さ・状態・チェックサム・初回受付を検証してから、取得tickの完全一致プリロード→トルクONの順に進む。
通信失敗・実測受付範囲外ではどちらにも進まない。

- 通常範囲内なら、その位置と左右差から操作を始める。
- 通常範囲外なら、取得位置をそのまま保持する。30%・HOMEへ自動移動しない。
- 左スティック両軸の中央復帰後の新しい倒し込みだけを受け付ける。最縮側の余裕外は↑伸長、伸長側は↓短縮。
- 左右に同じサーボ可動量%の変化を与え、位置を不意にそろえない。
- 必要な戻し方向が左右で矛盾する場合は `RETURN_DIRECTIONS_CONFLICT` として移動しない。
- 共通操作で片側が進行方向の端へ達した場合は `PAIR_LIMIT` として両脚を止める。片側だけ続行しない。
- 片側が通常範囲へ入っただけで、その側を止めない。両側が通常範囲へ入るまで共通の戻しを行える。
- 範囲外保持・戻し中は左右傾斜・AngleX補正を適用しない。
- 両側が通常範囲へ入ったときも送信位置を変えず、通常操作へ移る。

左スティック上下を中央へ戻すと指令位置を保持する。範囲への移行時に内部状態を整数指令へ対応付けても、
新しい目標への丸め移動は行わない。UARTの50 ms送信間隔による指令の送信遅れは従来どおり。
現在位置読取り・プリロードは物理位置の完全な同時性を保証するものではなく、外力下の過渡は実機で確認する。

## PS4操作と段階的な確認

現在の左右姿勢補正はP=3ポイント/度。[ゲイン変更・検証](leg-roll-p3.md)を参照。

| 入力 | 動作 |
|---|---|
| 左スティック上／下 | サーボ可動量を比例速度で伸長／短縮、最大12ポイント/秒、中央で保持 |
| 左スティック左／右 | 方向確認後だけ比例速度で傾斜目標操作、最大4°/秒・±3° |
| 左右を中央 | 確認済みの場合は既存4°/秒で目標0°へ戻す |
| 右スティック上／下 | 前進／後退。既存速度上限・加減速・ブレーキ・プロファイル |
| 右スティック左／右 | 既存旋回。電圧上限・出力余裕優先は不変 |
| 十字キー | 予約のみ。脚・走行・その他の指令を出さない |
| × | 既存の全停止＋脚OFF。支持試験の起点。通常運用の新しい停止仕様ではない |
| Share/u | 全解放後の支持試験有効化。脚移動・倒立開始はしない |

左は各軸の絶対値16以下を動作デッドゾーンとする。外側では
`(絶対値−16)/(端の絶対値−16)`で0～1に連続変換する。符号付き端は−128／+127をそれぞれ最大とする。
上（LY正）は伸長、下（LY負）は短縮、左（LX負）は左傾斜目標を正とする。高さ12 pp/s、RollRate4 deg/s、MaxRoll±3°は維持。
入力通知回数ではなく制御周期の実経過時間で更新する。新しいフィルターは加えない。
右のデッドゾーン±10、最大速度0.05 m/s、旋回0.10 V、更新ごとの速度／旋回ランプは変更しない。

**再操作の中央確認は左XY両軸±10以内**。動作DZ±16より狭くし、11～16の帯域では
指令ゼロでも中央復帰とは扱わない。接続／再接続、停止・転倒復帰、通信失敗、走行優先後は
左を中央へ戻してから新しく倒す。停止直前や切断前のデータは再操作に使わない。
範囲外保持も、最初の同期で現在tickを保持した後、中央復帰→新しい内向き操作の順。

`esp32dev`は `LEG_ROLL_DIRECTION_CONFIRMED=1`、`LEG_IMU_ROLL_SIGN=-1`。
実測AngleX−9.1°が左傾斜、左正角＝−AngleX。水平付近−0.9°のオフセットは追加しない。
左Xは従来のLX負＝左目標を維持し、物理方向は支持試験で照合する。
初回同期・範囲外復帰・切断後は取得／最終指令位置を保持し、新しい左右入力から補正する。
通常範囲内では目標−左正実測角を補正し、左右中央で目標を4°/秒で0°へ戻す。
範囲外保持・戻し中は左右操作・補正無効。詳細は[左右補正有効化](ps4-leg-roll.md)。

同時入力では右を優先し、脚は最後の位置指令を保持する。
支持試験でも右入力中は脚を保持するが、右だけで倒立・走行を開始しない。
走行・減速終了後に左が倒されたままでも再開せず、右中央→左XY中央→新しい左操作が必要。
十字キーは全解放・走行開始の条件にも使わず、押下／解放で脚や走行が変わらない。
他ボタンの押下・全解放と、初回接続時の両スティック中央確認は従来どおり。
更新が200 ms以上止まれば追いつき動作をせず、中央復帰・再操作を要求する。

外部電源のままでよい。バッテリー改造や電源種別判定を前提にしない。
車輪を停止・機体を支持しての試験と、静止倒立中の操作を区別する。
走行／減速中の脚操作は非対応。転倒・明示停止で脚OFFを優先し、復帰後は左中央・再同期から始める。
切断時は高さ増減を止め、HOMEへ動かさない。車輪再試行中は脚指令を保持して古い目標を再開しない。

## 手動試験・単独バス診断の監査

`src/main.cpp`のm/n/o/y/w/!/@/9、および`src/bus_diagnostic.cpp`のrhome/rext/lhome/lextも共通変換を使う。
有効なNVS設定から目標を生成し、旧HOME固定値を使用しない。有効設定がなければ拒否する。手動の絶対tick指定も通常範囲外ならON・位置送信前に拒否する。

| 操作 | 目標 |
|---|---|
| m / rext | 右10%＝2009 tick |
| n / rhome | 右の余裕内側最縮端＝2034 tick |
| o / lext | 左10%＝2116 tick |
| y / lhome | 左の余裕内側最縮端＝2094 tick |
| w、!、@ | 10%、20%、30%を通常範囲へ制限して送信 |
| 9 | 両側の余裕内側最縮端（実測0%端への移動ではない） |

これらは絶対位置へ動かす明示的な試験で、初回同期とは違う。
支持・停止状態で、現在位置からの移動量を確認した場合だけ使う。
単独bus_diagnosticは通常ファームと別であり、今回の更新のために書き込む必要はない。

## Web・USBシリアル診断

USBの定期脚詳細は既定OFF。Arduino IDE用の`:leg log on/off`・`:leg status`と
操作終了後のまとめは[シリアル手順](leg-serial-monitor.md)を参照。以下の連続値は詳細ON時だけ表示する。

Web「脚部操作・状態」は同じDOMの欄で、操作可否・同期・阻害理由・過去の操作失敗を分ける。
長文行は自然な高さへ拡張し、詳細は縦スクロールで読む。
下部の「初回受付範囲・サーボ設定」で実測0%／100%、両端余裕、初回受付、通常駆動範囲と戻し方向を表示する。
数値は `leg_calibration` / `leg_geometry` / `leg_accept` / `leg_position` のファーム設定・取得値から生成し、旧固定表示を使わない。
最終送信指令と取得tickは別欄にし、%を実長や機体高さとして表示しない。
Webの最終送信指令欄はPS4脚制御分で、手動試験の指令位置はUSBシリアルに表示する。
通常診断は1 Hz、選択測定項目のWebSocket JSONは1クライアント20 Hzのまま。
HTML/CSS/JSはdata配下、直列読込み、各8192 B以内、外部CDNなし。

シリアルは状態変化時に、同期開始・成功／失敗、取得tick・換算率、端点／範囲、許可方向、拒否理由を出す。
`LEG ACCEPTANCE: 初回受付範囲外`はUART異常や同期段階と別に表示する。
制御タスクでは固定長8件へ記録するだけ。既存HTTPタスクが後で最大48 B/処理、送信空き以下で出力する。
空きがなければ待たず、重要診断の欠落を明示する。連続軸・通常操作表示は別枠の最新値へ集約し、合計最大2 Hz。コールバック・受信処理内では出力しない。
正常時の受信生データや長押し入力を周期ごとに出力しない。失敗時生データだけ最大32 B。
シリアルを接続しなくても操作は同じ。

## 非同期位置応答の判別と失敗記録

既存ドライバーとFTServo_Arduinoの64922cda46e56b21b8c1d9e830d936a1941645aeを照合。
現在位置56/57はリトルエンディアン、bit15は符号、下位15 bitは絶対値。
完全一致READ／送信列エコーだけを分離し、分割受信を不正応答と決めつけない。
ID・長さ・状態・チェックサムを維持し、失敗側・期待値／取得値・時刻を固定長で保持する。
UARTは1 Mbps、RX16/TX17、サーボ速度150／ACC15。位置／既存処理のTX間隔50 ms、応答期限10 ms、同期250 ms以内。
[追従診断READ](leg-following-diagnostics.md)は別の500ms予算で位置指令を優先して追加する。
1周期最大16 RXバイト・1 TXフレーム（最大24 B）を維持し、応答待ち・flush・delay・無制限再試行は加えない。

## 読取り専用の位置測定・サーボ設定

×停止・脚OFF指令送信済み・機体支持後、Webの支持確認→「位置測定開始（動かさない）」で明示開始する。
Shareは不要。USBでは`(`開始、`)`終了。手で無理なく上下させる。支持状態は利用者が確認する。
既存UARTで左右交互にREADし、片側約10 Hzで現在／最小／最大tick、時刻・回数を固定長52 Bへ集計する。
受付判定やプリロードは使わず、正常な範囲外値も測定する。
取得tickの%もファームで算出して併記する。右では最小tickが最伸側なので、tickの最小最大と%の大小は逆になる。
位置・トルクON・サーボ設定の書込みを送らない。測定終了も駆動開始へつながらない。
通信失敗で終了し、正常取得済みの集計を保持。次の明示開始でリセットし、再起動で消える。
測定値は受付設定へ自動反映しない。最小最大はサンプル値であり、機械的安全範囲を保証しない。
送信領域待ちは非同期で最大1000 ms、シリアル集計は変化時最大2 Hz。

「サーボ設定を読む」は停止中に33番モードと9～12番角度制限をREADするだけ。
0＝位置、1＝車輪モード。設定値は書き換えず、前回／今回取得・失敗を分けて表示する。
サーボ内部0～4095と、実測端・通常駆動端は別の概念である。

## 維持する車輪条件

車輪PID・FULL・DLPF=0x03・保存FOC校正・右−1／左＋1・起立／転倒復帰・センサー再試行・PS4の他ボタン割当は変更しない。
脚の換算値をFOCのsensor_direction／zero_electric_angleや車輪方向係数へ転用しない。
既存の通信期限・WDT対策、スタック、UART／PS4 FIFO容量も維持する。

**ファームとLittleFS両方を更新する。** 以下のuploadは利用者が支持・停止手段を準備して行う。

```sh
pio run -e esp32dev

pio run -e esp32dev -t upload
pio run -e esp32dev -t uploadfs
```

   10 tick余裕の十分性、動作方向、荷重時の挙動を確認するまで拡大しない。
7. AngleXと左右伸縮方向を確認した後だけ左右補正設定を検討し、最後に静止倒立中の小操作へ進む。
   走行併用・ジャンプ・自動起立／着地は対象外。

## 左右スティック割当更新の診断

`leg_stick`は、受信時刻、生LX／LY／RX／RY、左の正規化要求、適用脚入力、
走行速度／旋回の適用要求、ゲートflagsを同じSnapshotで送る。
適用要求は既存プロファイル・最終可動端／電圧制限前であり、実位置・実速度ではない。
拒否時・中央時は適用0。範囲外・再操作ゲート中は要求があっても適用左右0。
flagsは入力解放ゲート1／左中央2／右優先4／走行入力ゲート8／左右方向確認16／生値取得32／接続64。
受信時刻は実際のイベント時刻で、保持tickで新しい受信時刻を付けない。
Webは下部「脚入力・許可判定」で表示し、通信停止時は最終受信情報と明示する。
シリアルは生値または適用ゲート／入力が変化した時だけ、別枠の最新値へ集約して最大2 Hzで後から出す。
同じ保持通知やタイムスタンプ更新だけでは出力しない。

切断時は未送信の位置増分を破棄して最後の送信指令位置を保持する。
初回同期途中の切断は、読取り専用診断を除いて同期を中断し、プリロード／ONを続行しない。
既存の車輪切断時停止方針・×・フォールト条件は変更しない。

実機確認は、ファーム＋LittleFS更新後、機体を支持し×→両スティック中央・ボタン解放→Share→解放。
左Yの小さな倒し量→中央保持→最大倒し量、左X左右の符号と斜め入力、十字キー無出力を確認する。
範囲外では保持→左中央→内向き操作を確認する。支持試験の右操作で倒立しないことを確認した後、
静止倒立中の左操作、最後に安全を確保して右の走行・旋回・中立減速を確認する。
走行／切断／停止／転倒／通信失敗後の左倒しっぱなしが再開せず、中央からの新しい操作だけを受けることを見る。
これらの新割当の実機成功、左車輪不動の改善は未検証。
