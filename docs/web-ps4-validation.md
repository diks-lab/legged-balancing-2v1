ホストで確認した主要条件：

- 接続のみ、押しっぱなし、スティックが倒されたままの開始/再接続では開始しない。
- Options/△/脚操作は押下エッジで処理する。初回の全入力解放と開始後の中立を必要とする。
- 前進/後退/旋回は既存の走行開始ゲートを通り、中立と切断は保留取消/ソフト停止へ進む。
- ソフト停止中もFULL/ATTITUDE+SPEEDで速度項の反転を保持する。
- 開始拒否が既存の走行要求を破壊しない。全停止はドライバーを無効化し、Shareでは開始しない。
- 旋回の左右差分・スルー制限・電圧余裕による制限、脚の上下限と走行中の拒否。
- マウント失敗/ファイル欠落時の503/404はモーター/倒立状態を変えない。
- HTTP指令を制御ループで処理する。CSV取得後にライブバッファを書き換えてもコピーは変わらない。
- 転倒時の出力遮断、記録保持、転倒後のCSV列と停止理由、拒否された再開始による非消去。

これらはハードウェア入出力・通信・機体の物理応答の検証ではない。
利用者確認済みなのは基準コミットのFULL静止自立である。
変更後の静止倒立、走行・減速・停止、旋回、脚操作と通信断検出の実機挙動は未検証。
HTTP低速クライアント併用時の最大制御周期とスタック/ヒープ余裕も実機計測が必要。
旋回は差動電圧指令であり、角速度制御や中立後の物理的な制動性能は検証していない。
既存のシリアル大量出力やサーボ通信による待ち時間は残る。

実機へのファーム/data書き込みと既存PRのマージは実施していない。

## HTTP起動失敗への追補

実機 `9bae8ef` で両輪FOC初期化後にHTTPタスクの動的作成失敗が報告された。
その起動ログには空き量・エラーコードがなく、総量不足/断片化の切り分けは未完了。
修正では8 KiBのスタックを維持して16-byte整列の静的領域とTCBを使用する。
CSVデータのコピー本体は19,968 Bから10,752 Bへ9,216 B削減
（速度60 B×128、周期24 B×64、制御84 B×128の同時保持を最大1種類へ変更）。
各サイズにコピー管理メタデータは含まない。元のリングバッファは削減しない。
削減分から8,192 Bのスタック予約を賄い、TCB等を含む実サイズは起動ログで表示する。

- `python tests/http_startup_host/run.py`: 成功。実際の起動関数でタスク生成前後の診断、
  8 KiBの静的スタック引渡し、Wi-Fi前の生成、準備完了通知、キュー/タスク失敗時の
  後始末、マウント失敗時の非フォーマット継続、重複起動抑止を確認。
- 既存drive_host: 成功。3種類のCSVごとの独立コピー、前回タイムアウト中の
  要求種類の上書き拒否を追加。PS4・符号・転倒時記録の既存試験も成功。
- attitude_hostの3系統とwheel_hostの51シナリオ: 成功。
- 初期のESP32ビルドは依存ツール取得中のチェックサム不一致で再試行となった。
  テレメトリー通信が自動レビューで拒否されたため、設定無効をコードで確認し、
  `PLATFORMIO_SETTING_ENABLE_TELEMETRY=no` で再実行した。
- 修正後 `pio run -e esp32dev`: 成功。RAM 111,756 B、Flash 1,907,797 B。
  ESP32用オブジェクトでスタック8,192 B、TCB 340 B、CSVコピー10,776 B
  （管理情報24 B含む）を確認。既存ライブラリの警告は残る。
- 修正後 `pio run -e esp32dev -t buildfs`: 成功。data内容の変更なし。

ホストのRTOSダブルは実機ヒープ・タスクスケジューリングを再現しない。
修正後の実機HTTP起動成功、CSV通信後のスタック余裕、Wi-Fi/PS4併用時の
最大制御周期は未確認。PID・FOC・PS4操作・停止条件は変更していない。
