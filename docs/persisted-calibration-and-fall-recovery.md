# 保存校正による通常起動・転倒後の自動復帰

> 最新の転倒復帰は [範囲進入周期での即時復帰](immediate-fall-recovery.md) を参照。
> 以下の1.5秒保持・角速度／車輪速度の静止待ちは撤去済み。保存校正と通常起動の即時開始は維持。


基準先頭bacfcaf、ブランチcodex/2208-web-ps4、PR #13。
**保存値が有効なら正常初期化直後に倒立制御開始。転倒停止だけは直立保持で自動復帰する。**
右−1／左＋1、PID、FOC設定、制御フィルター、PS4操作と起動モードATTITUDE_ONLY、
転倒／異常の閾値・連続確認時間、通信期限・WDT対策・スタック／FIFOは変更しない。
**倒立直後の強い振動は未解決。この変更で改善したとは扱わず、表示の平滑化も追加しない。**

## 通常起動

1. 既存I2C資源・LittleFS・Wi-Fi/IP・HTTP等の必須条件を確認する。
2. NVS保存値を検証し、IMU校正・センサーを確認する。
3. 保存値が無い／無効なら、車輪ドライバー・モーター初期化へ進まずENを遮断して「要校正」。
   **初回でも自動校正回転しない。** IMU取得が可能なら待機中も姿勢は更新する。
4. 有効なら左右sensor_direction・zero_electric_angleを適用し、SimpleFOC 2.4.0標準の
   校正省略経路を使用する。保存済みPP合格値はアプリの受理に用い、今回PPを測定したとは扱わない。
5. 正常初期化と最初の正常な測定が成立した周期に、目標角0°・その時点の車輪位置原点で制御開始。
   u／t、±2°開始待ち、1.5秒安定待ち、2秒準備、起動姿勢の基準角取得は追加しない。

通常起動ログの `source=SAVED_PP_PASS`／`pp=NOT_RUN`／`zero_measured=0` は、
今回走査せず保存値を復元した意味。明示校正は `source=MEASURED` と今回のPP結果を表示する。
校正走査を省くことと、初期化後の倒立駆動をなくすことは別。
設定不一致・破損等で有効値が選べなければ、始動操作でも初期化を飛び越えない。

## 保存形式と失敗時の保護

NVS namespace `wheel-foc`、keys `slot0`／`slot1`。各52 B、左右一組で保存する。

| フィールド | 内容 |
|---|---|
| magic／version | 0x434f4632／1 |
| config | SimpleFOC版識別・左右極対数・PWM相順／EN・I2C配線／0x36・校正電圧／電源の32 bit識別子 |
| generation | 世代番号、32 bit wrap比較 |
| wheels[2] | 各direction（±1）、poles（7）、zero（有限・0以上2π未満）、PP合格（1） |
| checksum | 先頭48 BのCRC-32 |

固定幅整数・IEEE float、ESP32 little endian。構造体52 Bをstatic_assert。
PWM相順・極対数等は現在のオブジェクト／定数から識別子を計算する。
機械的な磁石／相配線の付け替えをソフトが自動検出するものではない。

両輪の今回校正成功・PP合格・タイムアウトなし・センサー正常・IMU校正成功を確認し、
出力を遮断してから旧有効スロットと反対側へ書込む。Preferences::putBytesの
nvs_set_blob／nvs_commit成功と、読戻し・CRC・全バイト一致を確認してから受理する。
旧有効スロットを消さない。次回起動は整合する最新有効レコードを選ぶ。
片側の途中書込み／破損があっても、残った正常レコードを利用可能。
最新有効レコードの設定が現在と違う場合は要校正にする。
校正・保存失敗時は停止し、正常保存値を上書きしない。
読戻し失敗時は新スロットの永続状態が確定できないが、旧スロットは保持する。

Preferencesの確保・flash書込みは停止中の明示校正のみ。運転中の制御周期では行わない。
通常起動の読込みも制御開始前だけ。HTTPタスクはI2C／NVS／モーター操作を行わない。

## USBなしの明示校正

磁石再取付け、モーター／センサー交換、相配線変更などで関係が変わった場合だけ必要。
脚／外装だけの変更でモーターとセンサーの関係が同じなら再校正不要。

1. PS4×等で明示停止する。機体を保持し、校正中の車輪回転に対応できる条件を整える。
2. Web下部「詳細診断」を開き「明示校正（車輪が動きます）」を押し、確認画面で実行。
   診断の「配信開始」とは別の操作。
3. POST /calibration/startは固定長コマンドキューへ渡すだけ。
   実際の停止／センサー／Web前提は制御側で再確認し、稼働中の要求は拒否する。
   202はキュー受付であり、校正成功ではない。状態欄で結果を確認する。
4. IMU校正中は静止。左右を順に明示走査。既存各6秒の監視・異常時両輪遮断を維持。
   中断は「校正中断」POST /calibration/abort。待機要求も取り消せる。
   走査中の中断はHTTPタスクがまずGPIOで遮断し、制御側が中断を確認して保存を拒否。
   校正が終了して出力を遮断し保存処理に移った後は、中断を409で拒否して保存結果を表示する。
5. 両輪合格・保存読戻し確認後は「保存完了・停止中」。**そのまま自動倒立しない。**
   PS4の既存の有効化・手動再開始を使うか、保持した状態で再起動して通常起動を確認する。
   再起動後、有効保存値があれば開始操作なしで倒立する。

失敗／中断時は出力遮断、保存しない。センサーのラッチ異常は従来どおり再起動が必要。
物理構成を変えたのに校正が失敗した場合、旧値が残っていても適合するとは限らない。
変更後の構成で明示校正に成功するまで、旧保存値による運転を行わない。
校正・保存は停止中の別経路で、PS4割り当てや通常の走行要求を変えない。
校正走査の相電圧は通常のmove指令とは別なので、校正中の指令メーターは不明表示にする。

## 転倒停止からだけの復帰

転倒停止時は従来どおり出力遮断・停止履歴記録。その後だけ専用の復帰意図を立てる。
IMU取得の有効性・鮮度、両輪センサー、保存校正・FOC ready、初期化完了を確認する。

- 姿勢は固定0°の±2°以内。
- 角速度は既存2 deg/s以下、車輪速度は既存0.8 rad/s以下。
- 連続1500 ms保持。角度／角速度／速度の条件が崩れたら時間をリセット。
- 成立後は既存の制御状態リセットを共用し、目標0°を保持、位置原点だけ復帰時に取得。
- 明示停止・センサー異常・FOC異常・校正要求等で復帰意図を解除。回復しただけで再始動しない。
- 既存の脚サーボ停止処理は維持。復帰で新たな脚操作は行わない。

Webは「角度範囲外」「角速度範囲外」「車輪移動中」「1.5秒保持中」「復帰完了」を表示。
現在の制御状態と最新停止履歴を分け、復帰後は倒立中を表示し、履歴のTILT_STOPと時刻は残す。
転倒後に明示停止した場合も、履歴を残しつつ明示停止・復帰解除を表示する。
1.5秒は転倒復帰だけに適用し、正常起動へ追加しない。

## Web画面・通信

通常上部は接続・現在制御状態・停止／復帰理由・校正状態。
取得時刻・age・IMU時刻／seq・欠落件数・最新停止履歴時刻は下部詳細へ移した。
内部の鮮度・連番・欠落・無効区間・通信切断時の不明表示は維持。
姿勢グラフ／左右ドーナツ／補助グラフ、ブラウザー60秒／1200点、1クライアント20 Hzも維持。

JSONメタデータへcalibration／recoveryを追加。通常のRESTORED／NONEで43 B/sample、
20 Hz時860 B/sの増加（TCP/IP等除外）。状態文字列の長さにより変わる。
任意の測定項目は選択したものだけ。固定JSON上限2048 Bは維持。
HTML/CSS/JSの9ファイル直列取得、LF／CRLFとも8 KiB以内を維持。
最大はdashboard.jsのLF 8,023 B／CRLF 8,165 B。手編集用ファイルを圧縮していない。

## 書込み対象・実機確認手順

**今回はファームとLittleFSの両方を更新する。** 通常のupload／uploadfsは校正NVSを消さない。
全flash消去・NVS消去は行わない。エージェントは書込み・マージを行っていない。

```sh
pio run -e esp32dev
pio run -e esp32dev -t buildfs
# 以下は利用者が保持・対象ポートを確認して実施:
pio run -e esp32dev -t upload --upload-port PORT
pio run -e esp32dev -t uploadfs --upload-port PORT
```

最初は保持・両輪を浮かせて起動し、未保存なら要校正と無回転を確認。
Web明示校正→両輪PP合格・保存完了後に停止維持を確認する。
再起動時は校正走査せず、正常初期化後に倒立駆動へ進むことを段階確認する。
**転倒後も直立保持1.5秒で車輪が再駆動し得る。** 復帰させない場合はPS4×等で明示停止する。
異常・明示停止後に姿勢を戻しても再始動しないことも確認する。
