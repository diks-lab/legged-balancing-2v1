# 初期化・異常理由の表示

基準ブランチcodex/2208-web-ps4、作業前d3a8e3d。
AGENTS.mdとdocs/upstream-origin.mdを確認した診断だけの変更。
CONFIG=0x03、PID、出力限度、保存FOC、右−1/左＋1、起立進入開始・転倒即時復帰、
停止条件は変更しない。失敗を無視して駆動する経路はない。

## MPU6050設定結果

Mpu6050Config.hのResultは16 B固定長。既存と同じ書込み・4レジスター読取り・
全取得後の照合順序を維持し、以下を区別する。

| 状態 | 判定 | 保持値 |
| --- | --- | --- |
| 未実行 | apply前 | 値未取得を−1で表す |
| 設定書込み失敗 | CONFIG書込みendTransmission(true)が非0 | CONFIG、期待値、tx |
| レジスター指定失敗 | 読取り用endTransmission(false)が非0 | 対象名・アドレス、期待値、tx |
| 受信長不足 | requestFrom(1)が1でない | 対象名・期待値、tx、実際のrx長 |
| read失敗 | readが負 | 対象名・期待値、tx/rx/readの戻り値 |
| 設定不一致 | 全取得成功だが値が不一致 | 最初の不一致の対象・期待値・取得値と戻り値 |
| 成功 | 全設定一致 | 最終ACCEL_CONFIG照合結果と4レジスター値 |

CONFIG、SMPLRT_DIV、GYRO_CONFIG、ACCEL_CONFIGを名前付き表示。
−1は未実行／未取得であり、受信した0xFFとは区別する。
起動Serialは固定256 Bへsnprintfし、Serial.printで表示する。
Print::printfによる動的確保を診断ログで追加しない。

Arduino core 3.0.3のWireではendTransmission(false)はnonStopを設定し、
実バストランザクションはrequestFrom側で行われる。
したがってtx=0/rx=0からNACK・タイムアウト等の物理原因は断定しない。
受信長不足を「レジスター指定成功／相手正常」とも解釈しない。

## 各部品の実行状態

IMU、右車輪センサー、左車輪センサー、右FOC、左FOCを独立に保持する。
未実行・実行中・成功・実行して失敗・先行処理による実行不可を区別する。

- IMU設定失敗: IMUは失敗、両FOCは「未実行：IMU設定確認失敗のため」。
- ドライバー／モーター初期化失敗: FOCを実行した失敗とはせず、対応する前提不足。
- initFOCを実行して失敗: タイムアウト・センサー異常・中断・生戻り値0・PP未合格を表示。
- センサー／保存校正／タイマーの前提が足りずinitFOCを呼んでいない場合は未実行。
- 左右AS5600は既存の最初の両センサー読取りで既に初期化される。
  IMU失敗時でも、その確認に成功済みならセンサーは成功、FOCは未実行となる。
- 運転中の車輪読取りは現在のerrorと最初の異常履歴を分離。初期化成功状態は維持し、
  [次周期再試行](wheel-read-diagnostics.md)の現在状態を左右別に表示。
  IMUのI2C失敗・非有限値も記録する。制御・停止判断への入力ではない。

旧fault bit 4は「FOC準備未完了」として扱い、そのbitだけからFOC実行失敗とは表示しない。
実行中のFOCを、並行したWeb障害の通知で「未実行」へ書き換えない。

## 最初の異常と後続状態

最初に観測・記録した異常名（最大31文字）と起動内msを再起動まで保持する。
GPIO遮断を先に行うセンサー／FOCタイムアウトの既存順序を維持し、その後に記録。
根本原因の確定ではなく、ソフトウェアが最初に観測できた異常の記録である。
後続の出力遮断・測定停止・最新停止履歴とは別の固定行に表示する。
IMU設定の最初の失敗詳細も、明示再試行で成功しても保持する。
初回設定失敗記録と、現在の各処理の実行状態を混同しない。
明示的な再初期化では各実行状態を更新するが、最初の異常履歴は消去しない。
校正中等の想定内の測定停止を、時間経過だけで新しい最初の異常にしない。

固定長HealthReport 64 Bを短い専用critical sectionで共有する。
通信タスクはセンサーやモーターへアクセスせず、そのコピーだけを使用。
コールバック内でログ出力・通信・確保・待機を追加しない。

Web上部の状態欄は維持し、折りたたみ詳細へ独立した診断行を追加。
通信切断・配信停止・受信鮮度切れでは「通信停止・最終受信時の情報」と表示する。
最終受信時の異常・遮断フラグを、現在も成立する状態とは断定しない。
姿勢と出力の無効化・測定時刻・欠落検出は維持する。

## 配信・ファイル

既存20 Hz sample/statusに短いdiagnosis配列を追加。別接続や履歴は追加しない。
順序: [最初ms,最初の異常名,IMU状態,右センサー状態,左センサー状態,
右FOC状態,左FOC状態,先行失敗コード,右FOC詳細,左FOC詳細,
MPU結果,レジスター,期待値,取得値,tx,rx,read,IMU失敗理由]。
コードの対応はHealthDiagnostics.hとdata/diagnosis.jsに定義。
既存2048 B JSON・固定送信領域・要求解析WDT対策・送信期限を維持。
全選択＋集計＋異常情報が上限内に収まる回帰試験を行う。

HTMLに大きな説明を詰めず、diagnosis.jsを独立した整形済みファイルとして追加。
index→CSS2件→JS8件の直列取得（合計11ファイル）を維持。
各ファイルはLF/CRLFとも8 KiB以内。

## 書込み・実機確認

**ファームとLittleFSを両方更新する。** 通常の書込みで保存FOC NVSを維持し、全消去しない。

```sh
pio run -e esp32dev
pio run -e esp32dev -t buildfs
# 機体保持・対象ポート確認後に利用者が実施。エージェントは未実施。
pio run -e esp32dev -t upload --upload-port PORT
pio run -e esp32dev -t uploadfs --upload-port PORT
```

機体を保持し傾けて起動、IMU校正中は静止。±2°に入ると即時駆動する仕様は不変。
起動ログの設定詳細とWeb詳細を照合する。
異常発生時は最初の異常・対象レジスター・未実行の後続処理・遮断を個別確認。
配信停止／ブラウザー切断時は最終情報の表示になることを確認。
動作中に配線を抜いて故障を作らない。異常注入はホスト試験で実施した。

ビルド・ホスト試験・Chromium＋模擬JSONの成功を実機成功とは扱わない。
実機でのI2C失敗理由の取得・画面照合・Wi-Fi/PS4併用時の余裕、起立/復帰/自立、
振動改善は未検証。マージ・実機書込みは行わない。
