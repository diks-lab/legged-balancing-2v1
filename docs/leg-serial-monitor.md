# Arduino IDE用の脚ログ

基準458a20b。取得時点でその後の変更はなかった。
AGENTS.md、upstream-origin.md、脚制御・送信／実位置診断の文書を確認した。
今回はUSB出力だけを整理し、左右操作が小さい原因の調査・制御調整は行わない。

## 通常表示

- 起動詳細は既存のSERIAL_DIAGNOSTICS=0、HTTP_MEMORY_STAGE_DIAGNOSTICS=0を維持。
  脚の実行時詳細ログも既定OFF。重要な起動結果・IP・停止・異常は維持する。
- 通常は操作開始／終了・許可／同期／範囲などの状態変化・通信異常発生／回復を表示する。
  操作のENDは入力終了であり、サーボの到達完了ではない。
- 静止時のLEG FEEDBACK、PS4 AXES/APPLIED、LEG MOTION: PROGRESSは出さない。
  正常な新しい実位置の取得時刻だけが変わっても、通常ログは増えない。
- 左右の読取り失敗は、同じ状態・issuesが継続する間は最初の1回だけ表示し、
  最初の正常応答でRECOVEREDを表示する。WAITINGを回復とは扱わない。
  失敗回数は出力設定に関係なく内部で数え、status／回復ログに表示する。
  同期用受信異常も同じID・issuesの重複を抑え、正常な再同期／読取りで通信回復を表示する。
  新しい明示操作の開始・拒否・同期失敗は、その操作の結果として別に表示し得る。
- 読取り専用の測定も開始／終了・異常を維持し、同じ測定中の定期表示は詳細ON時だけ。

## Arduino IDEでの操作

シリアルモニターを115200 baudにし、送信欄の改行を「Newline」または「Both NL & CR」にする。
次の文字列を1行ずつ送信する。LF／CRLF対応。大小文字・空白は下記のとおり。
改行なしでは確定せず、入力途中の文字が既存の1文字駆動コマンドへ漏れない。
ANSI画面更新・カーソル移動は使わず、通常の改行だけで表示する。

```text
:leg log on
:leg log off
:leg status
```

| コマンド | 動作 |
|---|---|
| on | 既存の上限付き脚詳細を有効化。連続診断は合計最大2件/秒で最新値へ集約 |
| off | 定期詳細とその保留記録を破棄。重要FIFO・操作境界・異常・まとめは消さない |
| status | 現在の確定状態を1回コピーし、あとから整形して表示。駆動・読取り開始はしない |

返信例は`LEG LOG: OFF ACCEPTED`、`LEG LOG: STATUS ACCEPTED`。
status用の2記録をまとめて確保できなければ`STATUS BUSY; retry later`。
返信を待ってから次のコマンドを送る。詳細設定はRAMだけで、再起動時OFFに戻る。
既存の`:leg begin`などの校正コマンドと同じ32B行パーサーを拡張し、衝突を避けた。

返信は4件まで固定長で保留。過剰送信では新しいコマンドを適用せず、
`COMMAND BUSY count=N; no action applied`で拒否数をまとめる。無制限に溜めない。
OFF時に既に送り始めた1行は、途中で切って次の重要行と連結しないよう、その行だけ完了する。
まだ送っていない定期行・後続行は流さない。1行の領域192B、1処理最大48Bは従来どおり。
USB未接続・送信空き0では待機せず、制御・UART・Webを続ける。

statusは次を同じ取得時点のコピーから表示する。

- 許可／阻害理由、同期・段階・支持／倒立モード。
- ready、balance、support、explicit_stop、moving、IMU、wheel_retry、calibration、polarity、PS4、入力ゲート。
- 計算目標／時刻、最後にUARTへ送れた左右tick／時刻、送信・待ち・失敗回数。
- 生AngleX、左正実測角、要求／適用傾斜目標、トルク送信状態。
- 左右の最終取得tick／取得時刻／READ要求時刻と状態、最新UART指令との差、異常回数。

`error=実位置−最新UART指令`（tick）。未取得・失敗・中断・1500ms超の古い取得はUNKNOWN。
`after_cmd=1`はREAD要求と取得がその指令送信後であることを表す。
statusは送信時点ではなく**要求を受け付けた時点のSNAPSHOT**で、各取得時刻も併記する。
UART書込み成功・READ正常応答だけではON受理や到達を保証しない。

## 操作終了後の1回まとめ

入力が中央へ戻った時点ではENDだけを表示し、到達扱いしない。
ログ側で次の条件を確認する。どの条件も駆動許可・停止判定には使わない。

1. 要求傾斜が0°へ戻り、計算目標と最終UART指令が一致。
2. UART指令が観測上100ms変化していない。
3. 左右それぞれに、その指令送信後に開始した新しいREADの正常応答がある。
   READ時指令の時刻も最新送信時刻と一致し、取得が1500ms以内。

成立したら`NEW_FEEDBACK (not arrival confirmed)`と左右差を1回表示する。
これは新しい実位置を確認できた意味であり、位置差ゼロ・機械の静止・到達確認を意味しない。
100msはまとめ出力の観測条件だけで、制御や入力を待たせない。
姿勢補正などによる指令継続中は成立しないことがある。

入力終了から最大4000msで判定を打ち切り、次の状態を区別する。

- COMMAND_CONTINUING：目標0°への復帰や指令更新が続いている。
- FEEDBACK_INCOMPLETE：左右の新しい応答が未完了／失敗／古い。
- INACTIVE：停止・切断などで脚制御を継続していない。

各脚のUNREAD／WAITING／FAILED／CANCELLED／STALEなども併記する。
新操作が先に始まれば旧まとめをSUPERSEDEDとし、新旧のsession idを区別する。
高速な操作境界・置換通知は固定長へ集約し、重要8件FIFOを圧迫しない。
OFFは重要8件FIFOを消さない。status／まとめは同時点の2記録を一組で入れる。
USB停止中などで既存FIFOが満杯の場合も待機せず、診断欠落をLEG LOG: droppedで明示する。
出力が遅れた場合も記録時刻を新しい値へ付け替えない。

## 維持と検証

実位置READは左右交互500ms／各脚約1Hz、位置送信50ms、10ms応答期限、
RX最大16B・TX最大1フレーム/サービスをそのまま維持。
制御側は固定長コピーと比較だけ。整形・Serial出力は既存HTTPタスクで行う。
追加タスク・センサー読取り・機体長期履歴・動的確保・同期出力／待機は作らない。
左右補正の式・P・4°/秒・±3°・上下12ポイント/秒・校正・範囲・車輪制御は変更しない。

試験：ホスト回帰23組、脚／UART／NVS／実制御／配信のASan/UBSan、ESP32ビルドが成功。
既定OFFの静止時無出力、ON/OFF、保留破棄・開始済み行の完了、単発の不変コピー、
新しい左右応答後のまとめ・指令継続／読取り失敗の期限・連続操作のID分離、
異常継続／回復・回数、LF/CRLF・過大行・返信混雑、USB空き0を確認。
実PS4処理→UART／Web用Snapshotで、OFF・ON・status・USB送信不可の
指令列／READ回数・取得更新が一致した。Arduino IDEや実機に接続した試験ではない。
Webソース変更はなく、ホストJS回帰も成功。

458a20b比で静的RAM84,700→84,764B（+64B）、Flash1,951,301→1,955,201B（+3,900B）。
ホストの記録器1208→1276B（+68B）、Record84B・出力器304Bは不変。
新しい状態は設定・異常回数／ラッチ・返信4B・まとめのタイマー／IDなどの固定値。
制御State548B、Snapshot1164B、ServoBus148B、WS送信領域、UART／PS4 FIFO、スタック設定は不変。
機体上のヒープや制御周期の実測・サーボの実追従成功は未検証。
