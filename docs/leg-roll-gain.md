# 脚左右Pゲイン：1→2ポイント/度

基準e59cce3。最新取得時点で追加変更なし。
AGENTS.md、upstream-origin.md、脚左右・追従診断・Arduino IDEログ文書を確認した。
利用者は入力受理・UART送信・実位置読取りの成功を確認済み。
今回の変更は小さい傾斜指令を段階的に増やすためで、通信異常の修正ではない。

実行コードの変更は`include/LegControl.h`の`RollGain=1`→`2`の1行だけ。
既存式の左右差＝P×（適用目標角−左正実測角）を維持する。
例えば誤差+0.5°では左右差の目標が+0.5→+1ポイントとなる。
右は共通伸長率に左右差を加え、左は差し引くため、各脚の補正量が2倍になる。
左右差の変化上限4ポイント/秒は同じで、レート制限中の瞬間値が常に2倍になる意味ではない。
可動余裕による既存の適用目標制限（余裕÷P）・最終範囲制限も維持し、端を超えて2倍にはしない。

維持：目標±3°・操作／中央戻し4°/秒・上下12ポイント/秒、符号、IMU、保存校正、
範囲／端余裕、初回完全一致保持、中央／再操作、範囲外戻し、サーボ速度150／加速度15、
送信50ms・実位置READ、車輪制御・PS4割当、詳細ログ既定OFF・操作終了後のまとめ。
他の制御調整・診断機能追加は行わない。

## 検証

- 同一の実制御ヘッダーをP=1／P=2でコンパイルして比較。
  制限に掛からない誤差±0.25／±0.5／±1°、制御周期1/5/10/20/50msの全30組で
  定常の左右差補正量が2倍になり、傾きを減らす符号を維持することを確認。
- 各周期の変化量が4ポイント/秒以内、共通高さ不変、tickが通常範囲内であることを確認。
  大きい誤差では元の範囲保護が効くことも確認。
- ホスト回帰23組、脚・UART・NVS・実制御・配信のASan/UBSan、ESP32ビルドが成功。
  実PS4処理→UARTの左右方向、中央戻し、範囲外補正禁止、再操作、ログ・まとめの回帰も成功。

静的RAM84,764Bで増減0B。Flash1,955,201→1,955,221B（+20B）。
制御構造体・通信量・バッファ・履歴・NVS形式は不変。
