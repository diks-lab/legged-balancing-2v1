# FOCアライメントの固定長観測

目的は、SimpleFOCの生戻り値・PP判定不合格と、走査中のソフトウェア出力遮断を区別すること。
極対数7、アライメント電圧2.0 V、既存の電圧設定、PP許容値0.5 rad、走査・待ち時間・
PID・転倒/停止条件・6秒のガード期限を変更しない。自動再試行や校正省略は追加しない。

## 観測の範囲

SimpleFOC v2.4.0 / commit `4f072b3` の `FOCMotor.cpp` に観測フックだけを追加する。
`scripts/patch_foc_observation.py` を通常のesp32devビルドのpreスクリプトで適用する。
元ファイル全体と適用後ファイル全体のSHA256（CRLF→LFのみ正規化）を検証し、再適用は無変更で成功する。
文字コードはUTF-8に固定し、元のLF/CRLFをバイナリ書き込みで保持する。
[Windows対応・不一致診断と読み取り専用コマンド](foc-patch-portability.md)を参照。
未知の本文、アンカー不一致、出力不一致ではファイルを書き換えずビルドを止める。
依存ライブラリのキャッシュへの手作業変更には依存しない。

5点だけを保存する。走査中のセンサー更新・電圧指令・delayは増減させない。

| bit | 点 | 値と時刻 |
|---:|---|---|
| 0 | ForwardBegin | 往路開始直前のキャッシュ済み `sensor->getAngle()` |
| 1 | ForwardEnd | 既存ローカル変数 `mid_angle` と取得後時刻 |
| 2 | BackwardEnd | 既存ローカル変数 `end_angle` と取得後時刻 |
| 3 | ZeroBegin | 既存ゼロ角測定区間の開始時刻。角度値は使用しない |
| 4 | ZeroEnd | 既存 `zero_electric_angle` とゼロ角測定完了時刻 |

開始点はキャッシュ取得であり、新しいI2Cサンプルを要求しない。
ForwardBeginは初期位置の静止を保証する値ではない。PP判定は従来どおりmid/endだけを使う。
`moved` は既存の判定値を保存する。移動不足の早期終了時は保存済みmid/endから同じ絶対差を得る。
`pp_observed=0` はPP判定箇所に未到達を示し、`pp_pass=0` と区別する。

右/左に固定長レコードを各1個保持し、既存のSimpleFOCメッセージは共通の512 B Printバッファへ
一時退避する。スキャン中に観測用Serial出力、配列ログ、動的確保を追加しない。
バッファ満杯時は領域を越えず、`debug_dropped` に退避できなかったバイト数を保持する。
成功・移動不足・PP不合格・タイマー開始失敗・センサー事前異常のすべてで、
両輪GPIOを遮断した後に、退避メッセージとその車輪の記録をまとめて出力する。
右の表示は右FOC終了後、左の表示は左FOC終了後。表示は次の処理開始までの時間を延ばし得るが、
アライメントの走査内には追加しない。

## ログの読み方

`FOC OBS wheel=RIGHT/LEFT` の各行を見る。

- `raw_initFOC`：ライブラリの生戻り値。`-1` は事前条件/タイマー開始失敗で未呼び出し。
- `pp_observed` / `pp_pass`：PPチェック実施有無と既存の結果。
- `accepted`：従来のアプリ判定。生戻り値、期限切れなし、PP合格、センサー正常をすべて要求する。
  Web起動条件など、呼び出し元のその後の起動ゲートは別に維持する。
- `timer_start/stop`：既存タイマーAPI戻り値。`-1` は未呼び出し。`expired` は既存フラグ。
- `sensors_ok` / `right_error/left_error`：既存のキャッシュ済み状態。新たにI2C照会しない。
- `valid_mask`：有効な観測点のbit。未到達の値や区間時間を0という測定結果として解釈しない。
- `start/mid/end`：キャッシュ開始角、往路終了角、復路終了角（rad）。
- `forward_delta/reverse_delta`：符号付きの終了角−開始角。`moved` はPP判定用絶対差。
- `point_us`：各点の観測開始からの時刻差。`forward_us/reverse_us/zero_us` は各区間の差。
  `total_us` は観測開始から、通常終了の遮断とタイマー停止処理まで。出力時間を含めない。

PP判定式は `abs(moved * pole_pairs - 2π) <= 0.5`、推定ppは `2π/moved`。
例えば生戻り値1、`pp_observed=1 pp_pass=0 accepted=0` は、ライブラリの初期化は返ったが
既存のアプリPPゲートで拒否した状態。zero角が得られていてもPP合格とは限らない。

## 遮断の記録

GPIOをLOWにした後で短いportMUX区間に入り、発生元別の回数と最初の時刻を保存する。
時刻はGPIO操作後のソフトウェア観測時刻で、GPIOエッジのハードウェア計測ではない。
カウンターは遮断の呼び出し回数であり、繰り返しLOWを書いた回数も含む。

| gate | 意味 |
|---|---|
| NORMAL_CLEANUP | 生initFOC終了後、または未呼び出し失敗時の通常遮断。成功時にも出る |
| TIMER | 既存6秒タイマーコールバックによる両輪遮断 |
| WEB_ABORT | 既存のWeb前提喪失ラッチによる両輪遮断 |
| RIGHT_SENSOR / LEFT_SENSOR | 既存センサーfaultコールバックによる両輪遮断 |
| LIBRARY_DISABLE | ライブラリの既存initFOC失敗分岐でdisable()した後の通知 |
| OTHER | その他の既存共通GPIO遮断経路 |

`first_us` を往路/復路終了時刻と比較する。
通常終了や、移動不足判定後のライブラリdisableを、走査不足の原因となった途中遮断と混同しない。
TIMERがPP測定後に発生した場合、PP不合格と後段のタイマー失敗を別に評価する。
計測区間外の遮断、外部電源・ドライバー内部保護などの電気的変化は、この記録だけでは分からない。

## 並行する診断

FOCの観測中はHTTP側のPS4診断送信・段階別メモリーログを後送りする。
起動失敗表示は固定の保留スロットへ保存し、測定後のHTTP処理で通知する。
HTTP起動通知とIP/URL通知も後送りし、同一IPへの再接続でも通知を維持する。
ネットワーク状態判定・HTTPタスク・Web喪失時のGPIO遮断は停止しない。
PS4コールバックの入力保持や停止要求、診断送信バッファを削除/初期化しない。
既にUARTへ渡したバイトの物理的な送信完了を待つflushは追加しない。

ログ退避によって測定時のSerial負荷は従来と異なる。この観測版で成功した場合も、
それだけで以前の失敗原因を特定したとは扱わない。今回の実機結果を別途確認する。

## ホスト検証

`python3 tests/foc_observation_host/run.py` は、使用中ライブラリの元のinitFOC/alignSensorと
パッチ後の両関数をコンパイルして比較する。成功・推定pp7.64/7.66・移動不足で、
生戻り値、PP結果、センサー更新数、電圧指令列、delay列が一致することを確認する。
アプリの実ラッパー・表示・GPIO遮断もコンパイルし、タイマー/Web/センサー由来の遮断、
事前異常・タイマー開始失敗、遮断後だけの出力、固定長バッファ上限、並行カウンターを確認する。
パッチの再実行と未知本文での書換え拒否も確認する。

これらは実機のセンサー角、アライメント成功、遮断原因、制御周期を保証しない。
