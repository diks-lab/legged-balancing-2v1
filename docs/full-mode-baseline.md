# FULL基本モードと静止調整版の比較

比較対象は `dfd4d0c` と変更前の `5068a9d`。今回、初期モードと自動起立／転倒復帰時の選択をFULLに変更した。
ATTITUDE_ONLY等は明示的な調整用選択として残し、手動開始では選択を維持する。
自動復帰では調整モードを引き継がずFULLへ戻す。

| 対象 | dfd4d0c | 現行 |
| --- | --- | --- |
| ソースの初期モード | ATTITUDE_ONLY | FULL（今回変更） |
| 姿勢基準 | 手動開始の準備・安定判定後の姿勢平均 | 自動起立／復帰は固定0° |
| 車輪位置原点 | 開始時に取得 | 起立／復帰時の現在位置を取得 |
| PID P（姿勢／角速度／位置／速度） | 1 / 0.08 / 0.1 / 0.25 | 同値 |
| FULL位置項 | −pid_distance(原点−位置) | 同式 |
| FULL速度項 | −pid_speed(目標速度−速度) | 同式 |
| ソフト停止の速度項 | +speed_controlへ上書き | FULLでは−speed_control（既承認修正） |
| 右／左の方向 | +1 / +1 | −1 / +1（再組付け後の実測に基づく既存修正） |
| IMU CONFIG | 当時の実機レジスター値は未確認 | 0x03、書込み・読み戻し確認 |
| FOC | 起動時アライメント | 保存済み校正を検証して適用 |

当時は実行時にモードを変更できるため、実機使用モードと実際の平衡角はソースだけでは確定できない。
当時のFULL静止自立成功という報告はあるが、基準角の数値記録はない。
当時のMPUライブラリ指定は未固定であり、実機で解決された版もmanifestだけでは確定しない。
固定0°と機体の平衡角の差は実測対象であり、前進の原因をモードだけに断定しない。
起動姿勢の基準角への自動登録やPID調整は追加していない。

## フィードバックとPS4走行

位置・速度は右−0.5、左+0.5で合成し、係数内に平均化を含む。さらに2では割らない。
左右指令出力には右−1、左+1を適用する。保存sensor_directionを手動上書きしない。

FULLの静止位置保持は姿勢・角速度・位置・速度項を合成する。
PS4前後走行中の既存プロファイルは、位置項と直接速度項を抑制し、目標速度から微小目標傾斜を作る。
この区間のspeed_control計算値が直接出力に加算されるわけではない。
中立でのソフト停止では既存速度P=0.25と負符号を使い、その後位置保持へ移る。
今回このプロファイルや1.25倍の既存走行係数は変更していない。
FULLで走行中も4項が常時有効とは扱わない。

起立／復帰は既存開始関数を使用し、全PID状態、走行要求、目標速度・傾斜、旋回バイアス、速度フィルター状態をリセットする。
目標角0°とその周期の車輪位置原点を設定する。
±2°への進入での即時開始、正常性・鮮度確認、明示停止・異常からの自動再始動禁止は変更しない。

## 検証と更新

ホスト試験では、別の調整モードからの自動起立／復帰がFULLになること、原点と状態のリセット、
静止時の位置・速度項の符号、PS4走行プロファイルと中立減速、手動調整モードの維持を検証する。
実機の振動・走行・減速・位置保持・平衡角は未検証。成功を保証する変更ではない。

この差分の書込み対象は通常ファームのみ（`pio run -e esp32dev -t upload`）。
`data`に変更はなく、5068a9d対応LittleFSを使用中なら再書込み不要。
実機書込みは実施していない。
更新後は車輪が接地しない安全な支持状態で起動ログのFULLと方向を確認し、
従来の停止手段を準備して、直立範囲進入時の開始・停止・復帰、PS4中立減速を順に確認する。
固定0°付近の姿勢、目標傾斜、平均速度、位置誤差、各項、左右指令電圧を同時記録し、平衡角との差を確認する。

### 今回の実行結果

20組のPythonホスト回帰、シリアル診断ONの走行回帰、ASan/UBSan付き走行回帰、
姿勢・Web履歴／購読のホスト回帰が成功した。ESP32ビルド成功。
実ブラウザー・実機試験は今回実施していない。
ビルド集計はRAM 81,548→81,540 B（−8 B）、Flash 1,913,033→1,913,029 B（−4 B）。
初期列挙値と配置の変化による差であり、スタック・FIFO・履歴容量の削減はない。
通信項目・周期・送信量、LittleFS内容は不変。
